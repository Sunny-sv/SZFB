# 二、要解决的问题

|**版本**|**问题**|
|---|---|
|V1\.0\.0|1. **提成核算无差异化，激励机制失效**：皮带机全环节提成采用统一计算规则、全员平分的模式，未区分卸车、码货、移动不同作业环节的劳动强度、作业难度与工作量，无法体现多劳多得，易打击作业积极性，引发作业推诿、效率低下等问题。<br>2. **货量归属模糊，统计数据失真**：当前皮带机作业仅统计固定卸车总货量，卸车、码货、移动全环节作业人员统一平分货量，无法精准匹配不同岗位的实际作业量，货量归属不清晰。<br>3. **环节数据无法拆分，运营管理无依据**：无分环节的货量与提成明细数据，运营侧无法精准管控各作业环节效率、核算单环节运营成本，也无法针对性开展流程优化与人员管理。|
|V2\.0\.0|1. 子单明细只有目的网点，分拨侧不好按路由下一站透视货量，导出后要人工匹配，费事且容易错。<br>2. 无法直接看「哪条皮带机、哪个下货编号」货量高低，现场和给领导做表都要二次加工。<br>3. 查历史货量时若只套最新分拣方案/货区，对不上扫描当时实际走货。|

# 三、业务分析

## 3\.1  用户调研

|**版本**|**调研结果**|
|---|---|
|V1\.0\.0|皮带机卸车、码货、移动各环节的作业量、劳动强度差异显著，当前货量与提成全员平分的模式无法匹配个人实际作业贡献，有失公平；核心诉求为**将皮带机货量按卸车、码货、移动三个环节拆分，精准归属至对应作业人员；同时提成按三个环节分别设置规则、独立计算**，匹配各岗位作业特性。|
|V2\.0\.0|运营侧（对接）：要能按路由下一站、下货编号、皮带机看货量；子单要能导出皮带机编号、下货编号、路由下一站等字段自行透视；路由下一站/货区要以扫描当时数据为准，不要查最新。|

# 四、需求分析

## 4\.1 需求价值

|**版本**|**需求价值**|
|---|---|
|V1\.0\.0|1. **激励公平化，提升作业积极性**通过分环节货量精准归属、提成差异化独立计算，匹配不同岗位的实际作业贡献，真正实现多劳多得，有效激发一线作业人员积极性，减少作业推诿。<br>2. **数据精准化，保障核算准确性**拆分卸车、码货、移动各环节货量，实现作业量精准统计、归属清晰，保障出勤判定、薪资核算的准确性，减少人工核对与数据调整成本。<br>3. **管理精细化，提升运营管控能力**可获取各环节独立的作业与成本数据，支撑分拨精准管控各环节作业效率、核算单环节运营成本，针对性开展流程优化与人员管理。<br>4. **规则标准化，适配作业场景**支持按不同作业环节设置独立的提成计算规则，贴合皮带机全流程作业特性，实现薪资规则与作业场景的精准适配，提升分拨管理规范性。|
|V2\.0\.0|1. 系统内直接看皮带机、下货编号、路由下一站货量，减少导出后人工匹配。<br>2. 路由下一站、货区按扫描当时落数，历史查询可对上当时走货。<br>3. 子单字段补齐后，业务可自行透视做表。|

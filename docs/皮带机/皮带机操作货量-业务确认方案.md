# 【皮带机操作货量】业务确认方案

> 整理日期：2026-08-28  
> 需求负责人：胡绵飞  
> 说明：供业务确认「做什么 / 不做什么」。确认后据此写正式 PRD。  
> 对接口语里的「隔口 / 格口」= 系统字段 **下货编号**。

---

## 一、要解决什么问题

1. 子单导出只有「目的网点」，分拨侧不好按「路由下一站」透视货量。  
2. 要看哪条皮带机、哪个下货编号货量高低，现在要导出后人工匹配，麻烦。  
3. 看货量时，希望能对应到扫描当时走的路由下一站、货区。  
4. 下货编号希望能从 **0** 开始维护。

---

## 二、本期做什么（请确认）

### 1. 【皮带机设备维护】下货编号从 0 起

| 项 | 结论 |
| --- | --- |
| 生成规则 | 「下货编号数量」由现在的 `1～N` 改为 `0～N-1`。例：维护 5 → 0、1、2、3、4。**原因**：从 0 起同样「下货编号数量」下最大编号可少一位（如下货编号数量=10 时用 0～9，不必写到 10），操作工手写更方便 |
| 已有数据 | **不批量改**。已经是 `1～N` 的设备先不动；以后对该设备**重新编辑并保存**时，再按 `0～N-1` 生成 |
| 连带影响 | 【皮带机下货口管理】跟设备维护的编号走；【皮带机分拣方案】等用到下货编号的页面，按各设备实际编号集合使用 |

### 2. 【皮带机操作货量】子单明细加字段

在现有子单明细上增加（便于导出后自己透视）：

| 字段 | 说明 |
| --- | --- |
| 皮带机编号 | 扫描当时绑定的皮带机 |
| 下货编号 | 扫描匹配到的下货编号 |
| 路由下一站 | **扫描当时**按分拣方案匹配结果 **写入子单并保存**；之后查询、汇总都用这条当时数据，**不再查最新方案** |
| 分拣方案 | 扫描当时关联的方案名称/标识 |
| 目的分拨 | **货区路由的目的分拨**（建议扫描当时一并写入子单） |
| 货区编号 | **扫描当时**按路由下一站查货区维护 **写入子单并保存**；之后 **不再查最新维护** |
| SN码 | 扫描把枪的 SN |
| 货量类型 | 如普货、大票、集笼、空笼等（与现网操作货量明细一致） |
| 体积 | 子单体积 |

### 3. 【皮带机操作货量】数据汇总增加「皮带机」维度

| 项 | 结论 |
| --- | --- |
| 怎么加 | 在【数据汇总】里，现有下拉（分拨中心 / 外包公司）中**增加第三项「皮带机」**，与现网切换方式一致 |
| 字段 | **与「分拨中心」维度字段一致**（卸车 / 码货 / 移动吨位，以及网点·干线拆分、件数、票数、无归属等现有列都保留），多带出 **皮带机编号** |
| 汇总方式 | 按「分拨中心 + 皮带机编号」汇总，不拆到人 |

### 4. 【皮带机操作货量】新增 Tab「下货编号汇总」

| 项 | 结论 |
| --- | --- |
| 位置 | 人员汇总之后 |
| 名称 | 正式叫 **下货编号汇总**（对接时口语「格口汇总」） |
| 汇总方式 | 按「**分拨中心 + 皮带机编号 + 下货编号 + 路由下一站**」汇总（路由下一站、货区编号都取 **子单当时存的数**） |
| 结果形态 | **同一个分拨、同一条皮带机**下，会对应 **多条路由下一站** 行，每行带各自的货量相关字段（卸/码/移及网点·干线拆分等） |
| 列表合并 | **分拨中心 + 皮带机编号** 都相同的连续行：这两列一起纵向合并；同一分拨+皮带机下，同一**下货编号**对应多个路由下一站时，下货编号再纵向合并 |
| 勾选框 | 本页列表**无勾选框** |
| 货量列 | **卸车吨位、码货吨位、移动吨位** 三个汇总字段放在**前面**；**后面**再放网点 / 干线拆分字段（移动计泡与卸车、码货不同，不能只展一列） |
| 件数、票数 | **都展示**，口径与数据汇总同名字段一致 |
| 路由下一站 / 货区编号 | 展示子单当时值；**不**再套最新分拣方案 / 货区维护；**不**再把多下一站逗号拼在一格 |
| 不另加的列 | 不单独再加「分拣方案走货内容」 |

## 三、历史怎么看

- 路由下一站、货区编号以 **扫描当时写进子单的数据** 为准，查历史也能对上当时走货。  
- 分拣方案、货区维护以后改了，**只影响新扫描**；已经扫过的子单、已汇总出行 **不变**。  
- 本功能上线前已经产生、且子单上还没有这些字段的数据：汇总时可能为空——上线时是否补历史，正式 PRD 再定（默认倾向：仅新数据完整）。

---

## 四、明确不做（本期不做）

| 项 | 说明 |
| --- | --- |
| 卸车 / 码货 / 移动拆成三个页面 | 不做。一个页面里用字段区分，需要时排序即可 |
| 查询结果顶部加「操作人数」汇总行 | 不做 |
| 给领导看的日报类系统统计（件数、人数、人均吨位等自动出表） | 不做。临时监控继续人工做表 |
| 下货编号汇总只展示一列货量 | 不做（已否决）。必须卸 / 码 / 移都展 |
| 已有设备下货编号批量改成 0 起 | 不做。只在新建或重新编辑时按新规则生成 |
| 查报表时再套「最新」分拣方案 / 货区维护 | 不做。路由下一站、货区编号以子单当时存数为准 |
| 多下一站拼在同一格只展示、不拆行 | 不做。按下货编号汇总时按子单路由下一站拆行带货量 |

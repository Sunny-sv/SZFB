## 一、一页结论（给领导：为什么做、做什么、不做什么、预期收益、需要的支持）

### 为什么做

分拨排班仍偏经验驱动。货量按小时/环节波动、请假旷工、到车偏差叠加后，现场反复出现「人等多 / 货等人 / 忙闲不均」。智能排班要解决的是：**在可预知货量与班次约束下，更稳地决定「谁上哪个班、哪类岗」**，并把补位从口头拉人变成可追踪路径。

### 做什么（首期）

**【建议】首期只做人的班次/岗位：**

1. 货量→人力预测（分拨 / 环节 / 小时；路由粒度【待确认】）  
2. 班次编制（人数、岗位结构、建议名单；正式工/外包至少可区分展示）  
3. 调度确认后发布；员工可查本人班次  
4. 请假/旷工触发的**班次级补位**建议与时效记录  

采纳方式默认：**算法建议 + 调度确认**；已发布班表变更必须告知，禁止静默改写。

### 不做什么（首期硬边界）

| 不做 | 原因 |
| --- | --- |
| 车级微观指派（谁卸/装哪辆车） | 依赖到车/靠台/卡班数据深度；进阶能力，单列条件后再做 |
| 装车「排版」（车厢码放） | 与本题不是同一产品，禁止捆绑 |
| 默认全分拨、全环节、全工种一次开通 | 风险面与对接过重；必须白名单试点 |
| 无确认全自动改已发布班表 | 事故面与现场信任 |
| 替代考勤法定合规裁定 | 本系统不背合规结论 |
| 承诺「与 WMS/考勤/到车全部实时双向同步」 | 对接范围未定时禁止写进承诺 |

### 预期收益（方向；数值目标【待确认】）

- **班前：** 班次人数/岗位更贴预测货量，减少「人等多/货等人」  
- **班中：** 忙闲有统一口径；缺员补位可追踪（时长、是否达标）  
- **管理：** 发布准时、建议改动率可周报；为后续车级指派攒可信基线  

基线建议：试点启动前先采 **4 周** 再定目标值（见第七章）。

### 需要的支持（请领导拍板）

1. **试点分拨白名单**（建议 1 个主试点，最多再加 1 个对照）【待确认】  
2. **适用环节**（卸/装/移中哪个是主瓶颈）【待确认】  
3. **对接授权**：预测源、人员主数据、考勤只读请假/出勤；班表回写主从【待确认】  
4. **现场调度试点伙伴**：每周固定联调窗口 + 驳回原因必填  
5. **不扩范围承诺**：MVP 未准出前，不并行铺开全网或强上车级指派

## 二、目标与边界

### 2.1 目标一句话

**【建议】** 把分拨「人的班次与岗位编排」从经验驱动，变成：**预测驱动编制 → 调度确认发布 → 缺员可补位 → 指标可复盘**。

### 2.2 能力分层与首期停点

| 层级 | 含义 | 首期态度 |
| --- | --- | --- |
| L1 货量与人力预测 | 分拨/环节/小时「要多少人、哪类岗」 | **MVP 必做**（精度口径【待确认】） |
| L2 班次编制与发布 | 人数、岗位、建议名单；确认后发布 | **MVP 核心** |
| L3 车级微观指派 | 到车后卸/装/移指派到人/组 | **进阶；阶段4 可选** |
| L4 异常补位 | 请假/旷工等 | **MVP 做班次级**；车级随 L3 |

### 2.3 边界清单（可贴墙上）

| 类型 | 内容 |
| --- | --- |
| 做 | 班前编制、班中预警（班次级）、人机协同发布与变更告知、基础指标沉淀 |
| 慎做/后做 | 无完整靠台与车辆数据时的全自动微观指派；部分场景全自动发布 |
| 不做 | 装车排版；默认全分拨开通；静默改已发布班表；替代考勤合规裁定 |

### 2.4 明确非目标

- **不是**装车排版/码放项目。  
- **不是**一上来做「员工画像 → 精确到某辆车」的全量微观调度。DOC1 愿景可保留为远期，**【建议】不进 MVP 交付承诺**。

### 阶段0 对齐与试点选定（1–2 周）

**目标：** 范围写死、试点写死、不做清单签字；禁止「先做再说、默认全开」。

**做什么（检查清单）：**

- [ ] 对齐一页结论：做什么 / 不做什么 / 需要的支持  
- [ ] 选定试点分拨白名单（建议 1 个，对照分拨【待确认】）  
- [ ] 选定适用环节（卸/装/移；建议先主瓶颈环节）  
- [ ] 确认人机协同级别：默认「建议+确认」  
- [ ] 确认正式工/外包：至少名单区分；规则分叉是否并行【待确认】  
- [ ] 明确成功指标清单与基线采集计划（先采 4 周）  
- [ ] 输出《试点章程》一页纸（白名单、环节、不做清单、联调窗口）

**产出物：**

| 产出 | 说明 |
| --- | --- |
| 《试点章程》 | 分拨/环节白名单、边界、角色、周节奏 |
| 《待领导拍板事项》闭环表 | 见第十章；未决项不得假装已决 |
| 基线采集计划 | 指标、取数源、责任人、起止周 |

**准入：** 讨论稿已阅；产品/运营/现场至少一方可拍试点意向。  
**准出：**

- [ ] 试点分拨与环节书面【待确认→已确认】或明确延期原因  
- [ ] 不做清单无争议  
- [ ] 负责人角色占位齐全（可为兼职，但名字占位）

**负责人角色占位：** 产品（牵头） / 运营（试点协调） / 现场调度代表 / 数据 / 研发接口人。  
**风险：** 试点「暂不定」导致全员空转 → 对策：给领导两档选项（A 单试点 / B 暂缓立项），禁止无白名单开研发。

### 阶段1 数据与对接摸底（2–3 周）

**目标：** 摸清「排得准」依赖的最小数据与对接；缺口进清单，不在缺口上承诺精度。

**做什么（检查清单）：**

- [ ] 人员主数据：在职、岗位技能、用工类型、班次偏好来源与新鲜度  
- [ ] 出勤：请假/旷工接口实时性（只读优先）  
- [ ] 货量：历史/开单/在途/库存可读范围与延迟  
- [ ] 预测：是否已有可消费预测；粒度是否到「分拨+环节+小时」  
- [ ] 执行通道：管理台/员工查班入口——复用还是新建【待确认】  
- [ ] 班表回写：写回考勤/排班主系统还是本系统为主【待确认】  
- [ ] **MVP 最小对接集**成文（读什么、写什么、冲突以谁为准）  
- [ ] 到车/靠台/卡班：仅评估就绪度，**不作为 MVP 阻塞项**（留给阶段4）

**产出物：**

| 产出 | 说明 |
| --- | --- |
| 《数据字典与缺口表》 | 字段 / 源系统 / 延迟 / 是否 MVP 必选 |
| 《对接最小集说明书》 | 接口清单、主从、失败降级 |
| 《预测可用性结论》 | 有现成预测 / 需共建 / 人工导入过渡 |

**准入：** 阶段0 准出；试点分拨可提供取数联系人。  
**准出：**

- [ ] MVP 必选数据「有源可取」或「有过渡方案（如人工导入）」  
- [ ] 对接最小集无「全部双向实时」类空头承诺  
- [ ] 研发可据此拆 MVP 迭代；无法取数的能力降级或移出 MVP

**负责人角色占位：** 数据（牵头） / 研发 / 考勤HR（出勤口径） / 现场（校验名单真实性）。  
**风险：** 摸底变成「全系统打通愿景」 → 对策：只签 MVP 最小集；其余标【待确认】进 backlog。

---

### 阶段2 MVP：预测→班次编制→确认发布→班次补位（4–6 周）

**目标：** 在**白名单试点**打通主路径，可周发布、可查班、可补位、可留痕。

**做什么（按主路径拆）：**

1. **预测→人力**  
   - [ ] 输出未来 N 日各班「需要人数 / 岗位结构」（N 与「提前约一周」对齐，【待确认】）  
   - [ ] 界面展示预测新鲜度/缺失标记；数据差时允许降级人工编人数  

2. **班次编制**  
   - [ ] 结合技能、出勤、偏好、用工类型生成建议名单  
   - [ ] 正式工/外包至少区分展示；分规则编制【待确认】未定前不做自动强约束  

3. **确认发布**  
   - [ ] 调度调整 → 确认发布  
   - [ ] 员工可查本人班次（入口【待确认】）  
   - [ ] 发布后变更必须告知相关人；禁止静默覆盖  

4. **班次级补位**  
   - [ ] 请假/旷工（或人工登记）触发缺员  
   - [ ] 系统给补位候选人；调度确认  
   - [ ] 记录补位时长与是否影响班次人数达标  

5. **人机协同硬约束**  
   - [ ] 驳回原因可填、可沉淀  
   - [ ] 算法超时/数据缺失 → 降级人工并打标  

**产出物：**

| 产出 | 说明 |
| --- | --- |
| 可演示/可试用 MVP | 限白名单分拨+环节 |
| 《操作手册（调度版）》 | 发布、改班、补位、驳回 |
| 《发布与告知规则》 | 谁确认、谁收到、失败怎么办 |
| 埋点/日志清单 | 发布准时、改动率、补位时长等 |

**准入：** 阶段1 准出；试点调度完成操作培训窗口约定。  
**准出：**

- [ ] 连续 ≥2 个完整排班周期可走通「建议→确认发布→员工可查」  
- [ ] 至少完成若干次真实或缺员演练的班次级补位闭环（次数【待确认】）  
- [ ] 无「静默改已发布班表」类缺陷  
- [ ] 未纳入：车级指派、全自动发布、非白名单分拨  

**负责人角色占位：** 产品+研发（交付） / 现场调度（验收） / 运营（培训与周节奏） / 数据（监控新鲜度）。  
**风险：** 范围偷加微观指派 → 对策：变更必须走「阶段4 条件检查」；MVP 准出评审显式勾选「未做车级」。

---

### 阶段3 试点运行与指标复盘（2–4 周）

**目标：** 用真实运行证明「可运营」，而不是「可演示」；决定扩试点 / 修引擎 / 暂缓。

**做什么（检查清单）：**

- [ ] 按《试点章程》稳定周发布；固定周报复盘会（建议 30 分钟）  
- [ ] 采满基线对比窗：人效、班次人数偏差、预测误差、补位时长、发布准时率、调度改动率等（口径见第七章）  
- [ ] 驳回原因 TopN 归因（数据 / 规则 / 现场偏好 / 系统易用性）  
- [ ] 出《试点复盘报告》：继续 / 扩大白名单 / 回炉 / 不做阶段4  
- [ ] 明确是否满足进入阶段4 的**数据与组织条件**（见下）

**产出物：**

| 产出 | 说明 |
| --- | --- |
| 《试点复盘报告》 | 指标对比、案例、结论建议 |
| 《规则与模型修订清单》 | 下迭代优先级 |
| 阶段4 Go/No-Go 意见 | 条件清单勾选结果 |

**准入：** 阶段2 准出；基线数据可取。  
**准出：**

- [ ] 领导可见的复盘材料（一页结论 + 指标表）  
- [ ] 对「是否扩试点」「是否启动车级」给出明确建议（含否决理由亦可）  
- [ ] 未擅自扩大白名单至全分拨  

**负责人角色占位：** 运营（牵头复盘） / 产品 / 现场 / 数据。  
**风险：** 指标口径打架 → 对策：复盘会只认阶段0 签过的口径；新口径单列「下周期再生效」。

---

### 阶段4 V1.1 车级指派（可选，单列条件）

**目标：** 在班次能力稳定后，做「车 → 人/组」建议指派；**默认不自动启动**。

**启动条件（须全部满足，否则 No-Go）：**

- [ ] 阶段3 复盘结论为「班次能力可信、调度愿意继续用」  
- [ ] 到车系统可读：预计到达 / 靠台 / 卡班等关键字段，新鲜度可接受【待确认】  
- [ ] 明确优先场景：卸优先还是装优先【待确认】  
- [ ] 仍保持人机协同；不默认全自动改任务  
- [ ] 范围仍限白名单；禁止借 V1.1 全网铺开  
- [ ] 移动口级精度：数据就绪再开，否则降级到环节级【待确认】

**做什么（条件满足后）：**

- [ ] 到车更新 → 卸/装/移人/组建议  
- [ ] 压车/靠台变更/卡班 → 重算建议  
- [ ] 忙闲判断与补位联动（车级）  
- [ ] 单独准出标准与事故预案  

**产出物：** V1.1 范围说明书、对接增量清单、试点操作增量手册、独立复盘口径。  

**准入：** 上表条件全部勾选 + 领导同意启动。  
**准出：** 白名单内可稳定给出建议且调度确认路径完整；未满足则保持「班次产品」状态，不硬上。  

**负责人角色占位：** 产品+研发 / 到车系统接口人 / 现场调度。  
**风险：** 「调研愿景」倒逼并行开发 → 对策：无条件勾选不得排期；写入第十章待拍板。

## 五、组织与协作

| 角色 | 干什么 | 不做/注意 |
| --- | --- | --- |
| **产品** | 范围边界、分期、验收标准、人机协同规则、待拍板清单维护 | 不擅自把车级/全网写进 MVP |
| **运营** | 试点章程、培训、周报节奏、复盘组织、白名单变更管控 | 不私下扩开通分拨 |
| **现场调度** | 确认发布、驳回原因、补位决策、验收「能不能用」 | 紧急现场以调度为准；算法超时可降级 |
| **数据** | 字典、新鲜度、预测可用性、指标口径与取数 | 不承诺未摸清的「全量实时」 |
| **研发** | 按最小集交付；降级与告知能力；埋点 | 无确认不改已发布班表 |
| **考勤/HR** | 出勤/请假口径、用工类型规则协同、合规边界说明 | 本系统不替代法定合规裁定 |

**建议协作节奏：**

- 每日：试点联调问题跟进（阶段2 高峰期）  
- 每周：30 分钟周报（指标 + Top 问题 + 是否撞边界）

## 七、成功标准与汇报口径

### 7.1 基线怎么采

**【建议】**

1. 阶段0 定指标清单与口径草稿。  
2. 试点开通前或开通后并行，采集 **不少于 4 周** 基线（同环节、可对比班次）。  
3. 基线未齐前，周报只报「过程指标」（发布准时、使用率、改动率），不宣称「已提升 XX%」。  
4. 目标值在基线出来后由运营+现场+产品共同提，领导确认【待确认】。  

### 7.2 建议看的指标（口径均【待确认】）

| 指标 | 建议含义 | 周报是否默认展示 |
| --- | --- | --- |
| 发布准时率 | 约定时点前完成发布 | 是 |
| 调度改动率 | 建议名单被修改比例 | 是（解读：过高=不准，过低=可能未认真看） |
| 班次人数偏差 | 实际出勤 vs 发布人数 | 是 |
| 补位时长 | 缺员确认→补位到岗 | 是 |
| 预测误差 | 预测货量 vs 实际 | 是（有预测源时） |
| 人效 | 人均处理量或吨/票（分环节） | 基线齐后 |
| 压车时长/票数 | 到车后等待 | 班次期可选；车级期加重 |
| 忙闲均衡 | 班内小时人效波动 | 基线齐后 |

### 7.3 周报建议结构（一页）

1. 本周是否撞边界（扩范围/静默改班等）——有则标红  
2. 3～5 个核心过程指标 vs 上周  
3. Top3 驳回/失败原因  
4. 下周只做三件事  
5. 需领导/兄弟部门支持的 1 件事（可空）  

### 7.4 价值汇报口径（对外说法）

- **可说：** 试点范围内，编制可发布、补位可追踪、指标可对比。  
- **慎说：** 全网人效提升 X%、AI 替代调度。  
- **不说：** 已批准全分拨上线、已含车级微观指派（若未做）。

## 八、风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 范围膨胀 | 微观指派、全分拨、全自动并行 | 强制分期；白名单；准出勾选「未做车级」 |
| 数据不准 | 建议不可信，调度弃用 | 显示新鲜度；降级人工；缺口进阶段1 清单 |
| 组织阻力 | 「算法抢决策」 | 建议+确认；可驳回；禁止静默改班 |
| 用工/外包规则不清 | 自动强约束踩合规 | 规则未定前只展示区分，不强约束 |
| 与排版项目混淆 | 资源/结论串台 | 文档与评审分开；本文明确非排版 |
| 对接承诺过大 | 「全部实时双向」拖死 | 只签 MVP 最小集 |
| 无试点空转 | 研发已动、现场未定 | 阶段0 未准出不进大规模开发叙事 |
| 指标口径争议 | 复盘吵成方法论会 | 事前锁定口径；新口径下周期再生效 |

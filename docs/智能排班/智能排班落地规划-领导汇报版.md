## 一、一页结论（给领导：为什么做、做什么、不做什么、预期收益、需要的支持）

### 为什么做

分拨排班仍偏经验驱动。货量按小时/环节波动、请假旷工、到车偏差叠加后，现场反复出现「人等多 / 货等人 / 忙闲不均」。智能排班要解决的是：**在可预知货量与班次约束下，更稳地决定「谁上哪个班、哪类岗」**，并把补位从口头拉人变成可追踪路径。

与现网【转运人员排班维护】的关系：现网偏考勤与货量规则维护；智能排班是**预测驱动的班次编制与发布**，**不替代考勤法定合规裁定**。

### 做什么（首期）

**【建议】首期只做人的班次/岗位：**

1. 货量→人力预测（分拨 / 环节 / 小时；路由粒度【待确认】）
2. 班次编制（人数、岗位结构、建议名单；正式工/外包至少可区分展示；倒班间隔见 2.6）
3. 调度确认后发布；员工可查本人班次
4. 请假/旷工触发的**班次级补位**建议与时效记录

采纳方式默认：**算法建议 + 调度确认**；已发布班表变更必须告知，禁止静默改写。

**组织范围（已确认）：** 仅直营分拨中心、服务站；具体试点仓仍须白名单点名【待确认】。

### 不做什么（首期硬边界）

| 不做 | 原因 |
| --- | --- |
| 车级微观指派（谁卸/装哪辆车） | 依赖到车/靠台/卡班数据深度；进阶能力，单列条件后再做 |
| 装车「排版」（车厢码放） | 与本题不是同一产品，禁止捆绑 |
| 非适用组织类型开通 | 非直营分拨中心、直营集配站、非直营集配站本期不开 |
| 默认适用类型内全仓一次开通 | 风险面与对接过重；必须白名单试点 |
| 无确认全自动改已发布班表 | 事故面与现场信任 |
| 替代考勤法定合规裁定 | 本系统不背合规结论 |
| 承诺「与 WMS/考勤/到车全部实时双向同步」 | 对接范围未定时禁止写进承诺 |

### 预期收益（方向；数值目标【待确认】）

- **班前：** 班次人数/岗位更贴预测货量，减少「人等多/货等人」
- **班中：** 忙闲有统一口径；缺员补位可追踪（时长、是否达标）
- **管理：** 发布准时、建议改动率可周报；为后续车级指派攒可信基线

基线建议：试点启动前先采 **4 周** 再定目标值（见第七章）。

### 需要的支持（请领导拍板）

1. **试点仓白名单**（建议在适用类型内选 1 个主试点，最多再加 1 个对照）【待确认】
2. **适用环节**（卸/装/移中哪个是主瓶颈）【待确认】
3. **对接授权**：预测源、人员主数据、考勤只读请假/出勤；班表回写主从【待确认】
4. **现场调度试点伙伴**：每周固定联调窗口 + 驳回原因必填
5. **不扩范围承诺**：MVP 未准出前，不并行铺开全网或强上车级指派；不突破已确认的组织适用范围

## 二、目标与边界

### 2.1 目标一句话

**【建议】** 在直营分拨中心、服务站范围内，把「人的班次与岗位编排」从经验驱动，变成：**预测驱动编制 → 调度确认发布 → 缺员可补位 → 指标可复盘**。

### 2.2 能力分层与首期停点

| 层级 | 含义 | 首期态度 |
| --- | --- | --- |
| L1 货量与人力预测 | 分拨/环节/小时「要多少人、哪类岗」 | **MVP 必做**（精度口径【待确认】） |
| L2 班次编制与发布 | 人数、岗位、建议名单；确认后发布 | **MVP 核心** |
| L3 车级微观指派 | 到车后卸/装/移指派到人/组 | **进阶；阶段4 可选** |
| L4 异常补位 | 请假/旷工等 | **MVP 做班次级**；车级随 L3 |

### 2.3 边界清单（可贴墙上）

| 类型 | 内容 |
| --- | --- |
| 做 | 班前编制、班中预警（班次级）、人机协同发布与变更告知、基础指标沉淀 |
| 慎做/后做 | 无完整靠台与车辆数据时的全自动微观指派；部分场景全自动发布 |
| 不做 | 装车排版；突破组织适用范围；适用类型内默认全仓开通；静默改已发布班表；替代考勤合规裁定 |

### 2.4 明确非目标

- **不是**装车排版/码放项目。
- **不是**一上来做「员工画像 → 精确到某辆车」的全量微观调度。调研愿景可保留为远期，**【建议】不进 MVP 交付承诺**。
- **不是**替代【转运人员排班维护】的考勤规则配置能力。现网「装卸倒班」「移动倒班」是货量维护分类，不是本节倒班休息规则。

### 2.6 倒班间隔（班次切换休息）

现场没有「白班 / 夜班」固定叫法，各分拨按**班次时间**排班，一个分拨可以有若干个班次。倒班是：某人从当前班次换到另一个班次时，中间要不要空一天。

**已确认：**

| 项 | 结论 |
| --- | --- |
| 间隔怎么算 | 需要间隔时，中间**空一个自然日不上班**，不能上一班结束立刻接下一个班 |
| 违规怎么处理 | **只提示**，不拦截。调度看过提示后仍可确认发布 |
| 外包 | **另定**，不与正式工用同一套间隔规则；具体规则【待调研】 |

**待调研（未定前系统不自造班次对）：**

哪些班次切换必须空一天。例如从结束时间偏晚的班次换到开始时间偏早的班次要不要间隔，还是只有部分班次对要间隔。须到试点分拨问清现有班次时间表和现场习惯后再写规则。调研完成前，编制引擎**不按「夜班→白班」写死**。

### 2.5 材料结论摘要（三份飞书各自贡献什么）

| 材料 | 主要贡献 | 对本文的直接含义 |
| --- | --- | --- |
| 《智能排班系统调研》 | 问题清单覆盖班次、画像、上班前分配、突发、忙闲；目标可落到员工画像与微观指派 | 需求侧骨架已有；**不等于产品范围已定** |
| 《业务架构》 | 数据接入 → 预测/排班引擎 → 发布与员工触达 → 监控优化 | 可作为分层能力地图；各层首期做深到哪一步见上文停点 |
| 《基础数据》 | 人员、货流预测、车辆/靠台、装车货量、实时到车等字典雏形 | 「排得准」依赖的数据清单；缺口进阶段1，不在缺口上承诺精度 |

## 三、行业对照（精简可汇报）

**说明：** 装车「排版」（车厢码放）与本题「人的智能排班」不是同一题，此处不混用结论。

| 对照对象 | 公开能力要点 | 可借鉴 | 不做照搬 |
| --- | --- | --- | --- |
| 菜鸟运营平台 | 单量预测、智能排班、人效管理，强调现场可感知、可调度 | 「预测 → 排班 → 人效」闭环叙事 | 不照搬其产品包与上线范围 |
| 京东物流超脑等调度能力 | 货量预测、动态调度；公开能力常见分层为全自动 / 半自动 / 人机协同 | **采纳方式**：算法建议，人确认后生效 | 不照搬派车/末端调度模型到分拨排班 |
| 学术/行业路径 | 先做小时级货量预测，再按正式工/临时工（外包）约束优化班次人数 | 预测误差要进排班约束；用工类型分规则 | 不把对方模型精度直接当我方目标数字 |
| 通用仓库劳动力排班产品 | 按小时作业量曲线排班、空缺班次、换班、工时上限 | 班表发布、缺员补位、过程留痕 | 分拨还有靠台/到车/装卸移环节，不能当仓配通用 SaaS 直接套 |

**与我方差异（写入边界）：**

1. 首期停在**班次人数与名单**，车级微观指派后置。
2. 正式工/外包规则未定时：**名单区分展示，不做自动强约束**【待确认】是否并行定规则。
3. 组织范围已锁定为直营分拨中心、服务站，不按「全网物流公司都在做」扩开。

## 四、分阶段落地路线图

> 时间按「立项/对齐日起算」的相对周；具体日历与资源【待确认】。每阶段必须过**准入/准出**，未准出不进入下一阶段。

### 阶段0 对齐与试点选定（1–2 周）

**目标：** 范围写死、试点写死、不做清单签字；禁止「先做再说、适用类型内全开」。

**做什么（检查清单）：**

- [ ] 对齐一页结论：做什么 / 不做什么 / 需要的支持
- [ ] 组织适用范围宣贯：适用直营分拨中心、服务站；不适用其余三类
- [ ] 选定试点仓白名单（建议 1 个，对照仓【待确认】；须落在适用类型内）
- [ ] 选定适用环节（卸/装/移；建议先主瓶颈环节）
- [ ] 确认人机协同级别：默认「建议+确认」
- [ ] 确认正式工/外包：至少名单区分；外包倒班间隔另定，具体规则【待调研】
- [ ] 倒班间隔调研：列出试点分拨现有班次及起止时间；问清哪些班次切换必须空一个自然日（见 2.6）
- [ ] 明确成功指标清单与基线采集计划（先采 4 周）
- [ ] 输出《试点章程》一页纸（白名单、环节、不做清单、联调窗口）

**产出物：**

| 产出 | 说明 |
| --- | --- |
| 《试点章程》 | 仓/环节白名单、组织范围、边界、角色、周节奏 |
| 《待领导拍板事项》闭环表 | 见第十章；未决项不得假装已决 |
| 基线采集计划 | 指标、取数源、责任人、起止周 |

**准入：** 本规划已阅；产品/运营/现场至少一方可拍试点意向。  
**准出：**

- [ ] 试点仓与环节书面【待确认→已确认】或明确延期原因
- [ ] 不做清单无争议
- [ ] 负责人角色占位齐全（可为兼职，但名字占位）

**负责人角色占位：** 产品（牵头） / 运营（试点协调） / 现场调度代表 / 数据 / 研发接口人。  
**风险：** 试点「暂不定」导致全员空转 → 对策：给领导两档选项（A 单试点 / B 暂缓立项），禁止无白名单开研发。

### 阶段1 数据与对接摸底（2–3 周）

**目标：** 摸清「排得准」依赖的最小数据与对接；缺口进清单，不在缺口上承诺精度。

**做什么（检查清单）：**

- [ ] 人员主数据：在职、岗位技能、用工类型、班次偏好来源与新鲜度
- [ ] 出勤：请假/旷工接口实时性（只读优先）
- [ ] 货量：历史/开单/在途/库存可读范围与延迟
- [ ] 预测：是否已有可消费预测；粒度是否到「分拨+环节+小时」
- [ ] 执行通道：管理台/员工查班入口——复用还是新建【待确认】
- [ ] 班表回写：写回考勤/排班主系统还是本系统为主【待确认】
- [ ] **MVP 最小对接集**成文（读什么、写什么、冲突以谁为准）
- [ ] 到车/靠台/卡班：仅评估就绪度，**不作为 MVP 阻塞项**（留给阶段4）

**产出物：**

| 产出 | 说明 |
| --- | --- |
| 《数据字典与缺口表》 | 字段 / 源系统 / 延迟 / 是否 MVP 必选 |
| 《对接最小集说明书》 | 接口清单、主从、失败降级 |
| 《预测可用性结论》 | 有现成预测 / 需共建 / 人工导入过渡 |

**准入：** 阶段0 准出；试点仓可提供取数联系人。  
**准出：**

- [ ] MVP 必选数据「有源可取」或「有过渡方案（如人工导入）」
- [ ] 对接最小集无「全部双向实时」类空头承诺
- [ ] 研发可据此拆 MVP 迭代；无法取数的能力降级或移出 MVP

**负责人角色占位：** 数据（牵头） / 研发 / 考勤HR（出勤口径） / 现场（校验名单真实性）。  
**风险：** 摸底变成「全系统打通愿景」 → 对策：只签 MVP 最小集；其余标【待确认】进 backlog。

### 阶段2 MVP：预测→班次编制→确认发布→班次补位（4–6 周）

**目标：** 在**白名单试点**打通主路径，可周发布、可查班、可补位、可留痕。

**做什么（按主路径拆）：**

1. **预测→人力**
   - [ ] 输出未来 N 日各班「需要人数 / 岗位结构」（N 与「提前约一周」对齐，【待确认】）
   - [ ] 界面展示预测新鲜度/缺失标记；数据差时允许降级人工编人数

2. **班次编制**
   - [ ] 结合技能、出勤、偏好、用工类型生成建议名单
   - [ ] 正式工/外包至少区分展示；外包倒班间隔另定，规则未调研完前不做自动强约束
   - [ ] 倒班间隔：正式工在「已调研确认需要间隔」的班次切换上，中间空一个自然日；违规**只提示**，调度仍可确认发布。班次对未调研完前，不按夜班/白班写死规则

3. **确认发布**
   - [ ] 调度调整 → 确认发布
   - [ ] 员工可查本人班次（入口【待确认】）
   - [ ] 发布后变更必须告知相关人；禁止静默覆盖

4. **班次级补位**
   - [ ] 请假/旷工（或人工登记）触发缺员
   - [ ] 系统给补位候选人；调度确认
   - [ ] 记录补位时长与是否影响班次人数达标

5. **人机协同硬约束**
   - [ ] 驳回原因可填、可沉淀
   - [ ] 算法超时/数据缺失 → 降级人工并打标

**产出物：**

| 产出 | 说明 |
| --- | --- |
| 可演示/可试用 MVP | 限白名单仓+环节；限适用组织类型 |
| 《操作手册（调度版）》 | 发布、改班、补位、驳回 |
| 《发布与告知规则》 | 谁确认、谁收到、失败怎么办 |
| 埋点/日志清单 | 发布准时、改动率、补位时长等 |

**准入：** 阶段1 准出；试点调度完成操作培训窗口约定。  
**准出：**

- [ ] 连续 ≥2 个完整排班周期可走通「建议→确认发布→员工可查」
- [ ] 至少完成若干次真实或缺员演练的班次级补位闭环（次数【待确认】）
- [ ] 无「静默改已发布班表」类缺陷
- [ ] 未纳入：车级指派、全自动发布、非白名单仓、非适用组织类型

**负责人角色占位：** 产品+研发（交付） / 现场调度（验收） / 运营（培训与周节奏） / 数据（监控新鲜度）。  
**风险：** 范围偷加微观指派 → 对策：变更必须走「阶段4 条件检查」；MVP 准出评审显式勾选「未做车级」。

### 阶段3 试点运行与指标复盘（2–4 周）

**目标：** 用真实运行证明「可运营」，而不是「可演示」；决定扩试点 / 修引擎 / 暂缓。

**做什么（检查清单）：**

- [ ] 按《试点章程》稳定周发布；固定周报复盘会（建议 30 分钟）
- [ ] 采满基线对比窗：人效、班次人数偏差、预测误差、补位时长、发布准时率、调度改动率等（口径见第七章）
- [ ] 驳回原因 TopN 归因（数据 / 规则 / 现场偏好 / 系统易用性）
- [ ] 出《试点复盘报告》：继续 / 扩大白名单（仍限适用类型） / 回炉 / 不做阶段4
- [ ] 明确是否满足进入阶段4 的**数据与组织条件**（见下）

**产出物：**

| 产出 | 说明 |
| --- | --- |
| 《试点复盘报告》 | 指标对比、案例、结论建议 |

**做什么（条件满足后）：**

- [ ] 到车更新 → 卸/装/移人/组建议

## 七、成功标准与汇报口径

### 7.1 基线怎么采

**【建议】**

1. 阶段0 定指标清单与口径草稿。
2. 试点开通前或开通后并行，采集 **不少于 4 周** 基线（同环节、可对比班次）。
3. 基线未齐前，周报只报「过程指标」（发布准时、使用率、改动率），不宣称「已提升 XX%」。
4. 目标值在基线出来后由运营+现场+产品共同提，领导确认【待确认】。

### 7.2 建议看的指标（口径均【待确认】）

| 指标 | 建议含义 | 周报是否默认展示 |
| --- | --- | --- |
| 发布准时率 | 约定时点前完成发布 | 是 |
| 调度改动率 | 建议名单被修改比例 | 是（解读：过高=不准，过低=可能未认真看） |
| 班次人数偏差 | 实际出勤 vs 发布人数 | 是 |
| 补位时长 | 缺员确认→补位到岗 | 是 |
| 预测误差 | 预测货量 vs 实际 | 是（有预测源时） |
| 人效 | 人均处理量或吨/票（分环节） | 基线齐后 |
| 压车时长/票数 | 到车后等待 | 班次期可选；车级期加重 |
| 忙闲均衡 | 班内小时人效波动 | 基线齐后 |

### 7.3 周报建议结构（一页）

1. 本周是否撞边界（扩范围/静默改班/突破组织适用范围等）——有则标红
2. 3～5 个核心过程指标 vs 上周
3. Top3 驳回/失败原因
4. 下周只做三件事
5. 需领导/兄弟部门支持的 1 件事（可空）

### 7.4 价值汇报口径（对外说法）

- **可说：** 试点范围内，编制可发布、补位可追踪、指标可对比；适用范围为直营分拨中心、服务站。
- **慎说：** 全网人效提升 X%、AI 替代调度。
- **不说：** 已批准全仓上线、已含车级微观指派（若未做）、已覆盖非适用组织类型。

## 八、风险与不做清单

### 8.1 主要风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 范围膨胀 | 微观指派、全仓、全自动、非适用类型并行 | 强制分期；白名单；准出勾选「未做车级」 |
| 数据不准 | 建议不可信，调度弃用 | 显示新鲜度；降级人工；缺口进阶段1 清单 |
| 组织阻力 | 「算法抢决策」 | 建议+确认；可驳回；禁止静默改班 |
| 用工/外包规则不清 | 自动强约束踩合规 | 规则未定前只展示区分，不强约束 |
| 与排版项目混淆 | 资源/结论串台 | 文档与评审分开；本文明确非排版 |
| 对接承诺过大 | 「全部实时双向」拖死 | 只签 MVP 最小集 |
| 无试点空转 | 研发已动、现场未定 | 阶段0 未准出不进大规模开发叙事 |
| 指标口径争议 | 复盘吵成方法论会 | 事前锁定口径；新口径下周期再生效 |

### 8.2 建议「不做清单」（可贴墙上）

- 不做装车「排版」（货物码放）替代或捆绑。
- 不突破组织适用范围；不在适用类型内默认全仓一次开通。
- 不在无调度确认时全自动改已发布班表。
- 不以本系统替代考勤法定合规结论。
- 不在对接范围未定时承诺「与 WMS/考勤/到车全部实时双向同步」。

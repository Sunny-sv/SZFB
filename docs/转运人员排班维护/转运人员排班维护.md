# 二、要解决的问题

|**版本**|**问题**|
|---|---|
|V1\.3\.0|维护数据作用于考勤核算；员工当月中途离职后，发现配置有误或需新增配置时，因人员维度仅可选在职员工，无法对离职人员维护规则，影响当月考勤核算。|
|V1\.4\.0|月初算薪时常需改上月排班 / 货量 / 休息 / 打卡等方案；现网有效开始月份、每日货量日期不能早于当月，开始月早于当月时只能改结束月且不能删，次月起上月方案无法修正，影响考勤核算。|

# 三、业务分析

## 3\.1  用户调研

|**版本**|**调研结果**|
|---|---|
|V1\.3\.0|本维护页配置的数据实际作用于考勤核算。业务方反馈典型场景：某员工当月仅在职半个月后即离职；在其离职后发现为其配置的维护数据有误，或需为其新增配置，但系统人员维度仅允许选择在职员工，导致已离职人员无法查询、新增、编辑及导入，当月考勤核算所需规则无法及时修正。<br>调研结论：人员组件应放开离职限制，使查询与写操作口径一致；导入时以人事工号是否存在为校验边界，不因离职拦截。|
|V1\.4\.0|业务方反馈：算薪在月初，常发现上月方案配错或漏配，需要在系统里改上月数据。调研结论：对齐薪资侧维护页的「上月补录窗口」做法；本页单独配置截止日（默认 4 号）；全 Tab 放开；【每日货量维护】在放宽有效月份的同时，日期最早放开到上月 1 日。|

## 3\.2  产品方案

|**版本**|**产品方案**|
|---|---|
|V1\.4\.0|本页增加「上月补录窗口」：独立系统参数「上月方案维护截止日」（默认 4）。窗口内可新增 / 导入 / 全改 / 删除开始月为上月的方案，并允许截断长周期方案结束月腾空档；【每日货量维护】另放宽「日期」最早到上月 1 日（本 Tab 同时有有效月份）。窗口外沿用现网。维度、重复校验、人员含离职等其余规则不变。|

# 四、需求分析

## 4\.1 需求价值

|**版本**|**需求价值**|
|---|---|
|V1\.3\.0|1. **保障考勤核算准确性**：维护数据直接作用于考勤，支持对当月中途离职人员修正或补录规则，避免因选不到离职人员导致核算依据错误。<br>2. **缩短问题处理周期**：离职后发现问题可立即在系统内维护，无需绕行线下或找研发处理。<br>3. **改动范围可控**：仅调整人员可选范围及导入校验，不改变维度、有效月份、重复校验等既有逻辑。|
|V1\.4\.0|1. **支撑月初算薪纠错**：窗口内可改上月方案，减少线下补录与算薪差错。<br>2. **风险可控**：过截止日后恢复现网严控，避免长期可改历史。<br>3. **改动范围清晰**：只放宽时间窗与结束月下限；业务字段、维度、撞期规则不变。|

#### 每日货量维护

说明：本 Tab 在维度 / 条件之外，同时维护两类时间：
1. **日期**（到日）：保底货量 / 托数作用在哪些天（可多段，弹框内可「添加」）。

一条数据 = 选定维度下，在有效月份内，对指定日期执行每日保底。

# 二、要解决的问题

### V1\.0\.0

1. 运单被二级网点签收后，运单的目的网点会变成签收的二级网点，导致分拨必须维护二级网点的路由PDA才能扫描。

2. 针对产品中心拼多多线下单业务，订单来源不为“TEMU订单”，但是任需要根据目的二级网点匹配路由。但系统现在只能支持订单来源为“TEMU订单”的单号根据目的二级网点匹配路由。

3. 产品中心需开通航空业务，需要在现在已有的陆运路由的基础上再新增航空路由。

### V2\.0\.0

双库分拨下，网点交件与集配站交件的应交库区经常不一样，但面单首分拨库区标识仍只按「路由首分拨 + 路由目的分拨」取【分拨库区维护】一套配置。例如石家庄：网点开单目的为石家庄应打到达库标识，目的为梅河口集配站应可打出发库标识；与集配站/分拨交件共用同一套目的匹配时，特殊网点面单库区标识会打错，后续卸车、分库跟着偏。

# 三、业务分析

## 3\.1  用户调研

### V1\.0\.0

希望系统可以支持同一个寄件地址、目的地址可以同时支持陆运运输与航空运输。

### V2\.0\.0

- 网点开单、网点补打时，首分拨库区标识要按开单网点走【分拨库区维护 - 网点特殊配置】。
- 分拨-分拨段库区标识继续按现逻辑（路由下一分拨 + 路由目的分拨），本版不改。
- 未命中网点特殊的，首分拨仍按「路由首分拨 + 路由目的分拨」取通用配置。

## 3\.2 产品方案

### V2\.0\.0

仅**网点开单 / 网点补打**时，首分拨库区标识：先按「路由首分拨 + 开单网点 + 路由目的分拨」命中网点特殊（联查有效）取该行库区的**库区标识**；未命中则仍按「路由首分拨 + 路由目的分拨」取通用配置。分拨开单、分拨-分拨段匹配本版不改。

# 四、需求分析

## 4\.1 需求价值

### V1\.0\.0

1. 减少分拨人员维护路由成本

2. 试货区路由匹配的逻辑灵活性更高，如再出现需要用目的二级网点匹配路由及出现新的运输类型等情况，只需要修改分拨货区维护限制即可，不需要改变路由逻辑。

3. 给产品中心扩展新业务提供技术支持。

### V2\.0\.0

1. 网点开单/补打的首分拨库区标识与应交库一致，减少面单信息错误。
2. 与【分拨库区维护】V4、双库混卸提示取数口径对齐。
3. 分拨-分拨段不受影响，改动面可控。

#### 首分拨库区标识（网点开单 / 网点补打）

用运单的**开单网点**、**路由目的分拨**、**路由首分拨**（所属分拨），在【分拨库区维护 - 网点特殊配置】中按「所属分拨 + 开单网点 + 目的分拨中心」匹配，且联查通用主数据后**状态 = 有效**：

1. **命中**：首分拨库区标识 = 该条配置对应库区的**库区标识**（跟通用主数据实时取值）；**不再**按「路由首分拨 + 路由目的分拨」走通用匹配。
2. **未命中**：沿用现逻辑——路由首分拨 + 路由目的分拨匹配【分拨库区维护 - **通用配置**】中**状态 = 有效**的数据，取对应**库区标识**。

#### 验收要点

|序号|验收要点|
|---|---|

|2|网点开单/补打：未命中网点特殊 → 首分拨库区标识仍按「路由首分拨 + 路由目的分拨」取通用配置，与改版前一致。|

|4|分拨开单、分拨-分拨段库区标识匹配与改版前一致。|

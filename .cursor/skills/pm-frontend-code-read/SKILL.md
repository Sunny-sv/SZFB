# 读现网前端代码：字段必须读全

## 背景（禁止再犯）

曾画【转运人员薪资】原型时：虽在 TVM **uat**，但只读了页面片段 + 关键词搜索，再用 PRD/方案里的**增量改动**拼表头，导致列表/展开列与现网对不上（字段少、名不对）。后来才按 `personalSalary/index.vue` 的完整表头配置重对。

**根因不是分支，是读法：扫片段 ≠ 读现网字段。**

## 何时使用

- 根据 DLC / TVM 现网代码画或改原型（尤其列表、查询、弹框、展开行）
- 写/改 PRD 的查询条件、数据列表、导出字段，且要以现网为准
- 用户说「按代码对一下字段」「现网有哪些列」「字段不对」

配合：[dlc-frontend-source](../dlc-frontend-source/SKILL.md) / [tvm-frontend-source](../tvm-frontend-source/SKILL.md)（先定对项目 + **只读 uat**）→ 本 skill（**读全字段**）→ [pc-prototype](../pc-prototype/SKILL.md) 落原型。

## 硬约束

| 禁止 | 必须 |
|------|------|
| 只读文件前 100～200 行就定列表列 | 找到并读完**表头/列配置的完整定义**（如 `countHeader`、`detailHeader`、`columns`、`el-table-column` 全集、导出字段数组等） |
| 只 `grep`「大票提成」等改名关键词就画整表 | 先拿到**现网字段全集**，再在全集上做改名/新增/隐藏 |
| 用 PRD / 方案 / 对接纪要里的增量列表代替现网列 | 文档只作「本期改什么」；**列有哪些、叫什么、顺序**以 uat 源码为准 |
| 把 A 系统页面的字段套到 B 系统同名业务上 | 先确认页面在 DLC 还是 TVM，打开**对应仓库**的对应 `.vue` |
| 查询条件、按钮、Tab、展开行、修改记录只对一半 | 与列表同标准：各区域都从源码对全，再改本期差异 |

## 正确读法（清单）

对某一个现网页面动手前，按顺序做：

1. **定项目 + 分支**：DLC 或 TVM；确认 **uat**（见对应 frontend-source skill）
2. **定文件**：定位该菜单对应的页面入口 `.vue`（及拆出去的 table/column 子组件）
3. **读全配置，不要猜**：
   - 查询条件 / 筛选项
   - 内容 Tab
   - 操作按钮
   - 主表列（人员汇总、明细等每个 Tab 各自一份）
   - 行展开 / 子表列
   - 弹框 / 修改记录 / 导入导出模板字段（页面上有的都要对）
4. **再叠本期改动**：只在「已核对的现网全集」上改名、加列、删列；对话里可简述「现网 N 列，本期改哪几列」
5. **对不上就停**：源码里找不到、多文件互相矛盾、或不确定是否一线展示 → 按 `pm-ask-before-guess` **先问用户**，禁止用文档猜进原型

## 自检（落原型/写列表节前）

- [ ] 已确认 DLC / TVM，且源码来自 **uat**
- [ ] 已打开正确页面文件（不是同名业务的另一个系统）
- [ ] 主表 / 明细 / 展开 / 弹框等**各自**对照过完整列定义，不是只改了本期提到的那几个字
- [ ] 未用 PRD 增量列表冒充现网字段全集
- [ ] 本期差异（改名/新增）是在全集核对之后才写入

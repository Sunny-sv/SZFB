# PRD 写法规范

## 何时使用

- 写维护页、配置页、报表页 PRD 时
- 写已有功能新增、修改、版本增量说明时
- 用户说「只写改动」「不要废话」「按模块写」「AI 味不要太重」「原来那种写法」时
- 与 `pc-maintain-prd`、`pc-report-prd`、`pm-incremental-prd` 同时使用，本 skill 管写法风格
- 业务规则句式默认遵守下方「业务规则书面表达」；写完**不要**再自动跑润色
- 控件叫什么、说明列写差异不写常识：见 [pm-component-catalog](../pm-component-catalog/SKILL.md)
- 仅当用户明确要求对已有正文做结构化润色（分层、定义标准化、价值包装等）时：见 [pm-prd-polish](../pm-prd-polish/SKILL.md)

## 核心原则

|原则|要求|
|---|---|
|只写有用内容|只写本次新增、删除、调整的内容；不展开没改的内容|
|每版背景节必写|增量版本须写清「要解决的问题、用户调研、产品方案、需求价值」；业务分析中用户调研与产品方案两项都要写；不知背景先问用户（详见 [pm-incremental-prd](../pm-incremental-prd/SKILL.md)）|
|**缺信息先问、禁止瞎猜**|用户原话：如果你发现我给你的信息不完整，或者你做方案写文档这些需要其他我没给的信息要告诉我，我给你补充，不要靠你自己猜。详见 [pm-ask-before-guess](../pm-ask-before-guess/SKILL.md)|
|不写版本概述|不写「本版改动概述」「版本概述」总述小节；改动直接落在对应模块规则里|
|不改历史版本正文|多版本串联在同一文件时，不回改已发布的 `### V1.x` / `### V2.x` 等历史章节；本版规则只写在新建版本节（详见 [pm-incremental-prd](../pm-incremental-prd/SKILL.md)）|
|**需求描述下挂版本号**|「五、详细需求」里「需求描述」标题之下，规则正文按 `### V1.0.0` / `### V1.1.0` … 分节；**新建文档首版必须先写 `### V1.0.0`**，禁止用 `### 5.2.1` 等序号代替版本号（维护/报表见 pc-maintain-prd / pc-report-prd）|
|**按区域归类（强制）**|PC 端维护页 / 报表页 / 版本增量里凡涉及页面字段改动，**必须**拆到查询条件、按钮操作、数据列表对应区域写；**无用户明确要求时也要严格遵守**，不得写成一整段编号清单|
|**段首不复述三区（强制）**|Tab / 字段主题段首只留一句职责或跨区域短口径；选库、跟库、弹框字段、校验、删除联动、列表展示等**一律写进对应区域**，禁止在三区前面再铺一大段与后文重复的规则/字段表|
|**公共规则 vs 禁止复述开篇（强制）**|**允许**版本节内先写 `#### 公共规则`（可带「四个 Tab」等范围）：仅放多 Tab **共用且复杂**、写进任一三区会复制多遍的内容（跨页重叠提醒整套步骤、统一字段改名清单、四 Tab 共用字段默认值等）。公共节后各 Tab **仍进三区**；三区用「按上述「xxx」」引用，不重抄。**仍禁止**「本页做两件事」、把查询/弹框/列表细则提前抄一遍再进三区、改版背景长段、与三区重复的流程图总览；单 Tab 无跨区共用时直接进三区；枚举/拆分写查询条件，字段写列表，计算公式写列表子节|
|**验收要点用表（强制）**|验收要点用 `序号 \| 验收要点` 表格列出，禁止纯编号列表|
|不跨模块重复|维护页已说明、已禁止或大家评审时已确认的内容，计算/报表/其他文档不再重复写|
|删除就写删除|不要写「替代为」「由 A 替代」「同步更新配置项」「配置内容升级」|
|表格内分点|同一单元格里有多类信息时，用 `1.` `2.` `<br>` 拆开；多层判断用**缩进**表父子，不用同级假序号冒充层级|
|非字段不装字段|展示规则、合并规则、排序规则等放表格最后说明行，不放字段列|
|不重复原型已见内容|原型已确认时，不写页面骨架、模块顺序、有无 Tab、**有无勾选框**、查询/按钮/列表三区布局等界面复述；5.1 已挂原型链接即可。除非本版相对现网**改了**勾选/布局，才写进对应区域|
|按钮不写默认查询/重置|按钮操作表**默认不写**查询、重置（系统默认逻辑）；仅当用户点名有特殊逻辑时才写|
|结论先行少解释|**规则正文**直接写规则结论；不写改版对比长文、职责旁白、「因此本场景…」「也就是说…」。**背景四节**（要解决的问题、用户调研、产品方案、需求价值）允许分条、举例、产品方案下的「改动前后」小表，写法见 [pm-incremental-prd](../pm-incremental-prd/SKILL.md)「背景四节怎么写才够评审」|
|**同节不复述（规则类强制）**|流程图 / 步骤表 / 结果表已写清的分支与枚举，正文不再复述；表后只写尚未出现的增量信息（详见「描述密度与引用」）|
|重复规则引用|**复杂**共用规则（多步匹配、平分、门槛+公式等）只写全一次，他处可「按上述「字段名」xxx 规则」。**简单**查询条件（默认值、空不生效、一两句查询逻辑）各 Tab/各处**原样写全**，不要「按上述」。禁止跨历史版本 / 跨章节序号互引（见下节）|

## 描述密度与引用（对齐手动改稿，强制）

对照基准：用户在 AI 初稿上压缩后的写法（如移动错分归位 V1.2.0 手动改稿）。写 PRD 描述时默认贴合，不要写成「又全又长」的说明书腔。

### 必须做

1. **结论先行，少解释**  
   - 一行能说清就一行（如奖励：`逻辑修改：奖励金额等于本行「总处罚金额」。`）。  
   - 不写「和改版前的区别…」「本层只决定能不能扫…」「因此本场景只弹框不上传」这类旁白；非必要不解释「为什么这样写」。  
   - **改错后重写只写现行规则**：用户纠正后，直接按正确逻辑重写；不要写「以前写成只写卸车、现改为三份都写」这类纠错说明，也不要在个别字段上单独加「卸/码/移都要写」——同表其他字段没写的共性规则，不要只挂在改过的字段上（易让人误以为别的字段不同）。共性写在节首一句即可，字段说明只写本字段取值逻辑。

2. **重复规则：复杂可引用，简单写全**  
   - **复杂规则**（多步计算、平分、跨表匹配+门槛+公式等）：首次出现处写全；同版他处可 `按上述「错分卸车人处罚金额」平分规则`。  
   - **简单规则**（查询默认值、空不生效、精准/包含匹配等短说明）：每个 Tab / 每处**原样写一遍**，不要写「按上述「工号」规则」。  
   - **仍禁止**：`见 4.3`、`与 V1.1.0 一致（见上文）`、跨历史版本章节序号互引。

3. **条件用加粗标签**  
   - 推荐：`**操作方式=皮带机：**`、`**PDA 行：**`、`**扣罚判断：**`。  
   - 结果相同可合并：`**操作方式=PDA/流水线：**空`。

4. **复杂分支优先流程图**  
   - 嵌套深的扫描/归位判断：正文用「说明 \| 流程图」或短表，不把第 1～N 步长文再堆一遍。  
   - 关键结果可留在验收要点表。  
   - **流程图与步骤表二选一为主载体即可**；二者并用时，表后正文仍遵守下条「同节不复述」。

5. **同节不复述（规则类强制）**  
   - 同一版本章节内：流程图、步骤表、结果表已写清的分支 / 枚举 / 动作，**正文不得再用自然语言复述一遍**。  
   - 表/图之后只允许写 **尚未出现的增量信息**（如取值来源、衔接下一节的一句）。增量能并进表「补充说明」列则并进，避免单独再起解释段。  
   - **禁止句式**：`按上面…`、`分两种：…（上面已写）`、`以及 A/B/C（表里已列）` 这类总结腔。  
   - 适用于 PDA / 扫描 / 判定 / 货量规则等非三区结构的规则正文（维护/报表三区复述见下文「Tab / 模块段首禁止复述三区」）。

6. **长规格外挂附件**  
   - 导出完整列顺序、导出样式样例 → CSV / 说明文件，PRD 按钮说明只写本版差异（如按人拆行）。  
   - 查询条件「依次追加在某某后」、列表「紧挨某某列之后」等位置类说明：原型已定时不写。

7. **未改写一句**  
   - `xxx 录入/逻辑沿用现网，本版不改`。不要为「对齐」再抄一整张现网字段表。

8. **用词贴现网、维度可落地**  
   - 状态/来源/处理人等枚举跟页面一致（如「系统已处理」「系统导入」「自动处理」）。  
   - 汇总维度优先写「同一个人事工号」等可落地字段，少用空泛「同一个人」后再解释工号规则。  
   - **节名偏业务结果**（如「判断是否录入奖罚」「写入货量明细的字段」），少用「0.01 判定」这类符号标题；**禁止**用「落数」「固化」「分桶」等当节名、修订说明或跨文档引用锚点。

9. **列表已写清的计算，下游只写用哪个数**  
   - 推送/录入不要再把「总处罚÷总人次」全文抄一遍；写「取个人处罚金额之和」即可。

### 正例 / 反例

| 反例（勿写） | 正例（按此写） |
|---|---|
| 奖励金额：1. 取值=总处罚。2. 和改版前的区别：多条时不再二次相除…3. 所有行均展示… | `逻辑修改：奖励金额等于本行「总处罚金额」。` |
| 错分卸车/码货/移动处罚金额各抄一遍完整平分规则 | 平分写在一处；另两处 `按上述「错分卸车人处罚金额」平分规则` |
| 三 Tab 工号都写「按上述「工号」规则」 | 各 Tab 工号说明各自写全：默认空、不参与过滤、人事工号包含输入内容 |
| 导出一格写满列顺序+人员列+公共字段+列表展示 | 拆行规则 3 点 + 链接导出样式 CSV |
| 查询表下脚注「依次追加…」「现有条件仅改口径」长说明 | 能在字段说明里用「现有条件，本版改匹配口径」带过即可 |
| 「以前只写卸车，现改为三份都写」；体积说明里单独写「卸/码/移都写」而同表皮带机编号不写 | 字段说明只写取值（如「子单体积，单位 m³」）；共性由节首「写入货量明细」覆盖 |
| 页面展示开篇：「本页做两件事」+ 把查询/弹框/列表细则提前抄一遍，后面三区再写一遍 | 无跨 Tab 共用时直接 `##### 查询条件` → `##### 按钮操作` → `##### 数据列表`；有四 Tab 共用的重叠算法/改名清单时先 `#### 公共规则`，再各 Tab 三区并用「按上述」引用 |
| 字段改名在每个 Tab 查询/按钮/列表各抄一遍新旧对照长文 | 公共规则列改名清单；三区对应格只写「原××改名，规则沿用现网」 |
| 步骤表已写「中心派车提货不进操作大票」，后又整段复述提货/送货方式枚举与分支 | 步骤表后只留增量：`提货方式、送货方式取值按现网大票专线/大票直送。` |
| 节名「货量落数」；正文「子单落数字段」；互引「见本版「货量落数」」 | 节名「写入货量明细的字段」；正文「扫描成功时在货量明细上写入下列字段」；互引用同一业务节名 |

### 表格嵌套

```markdown
1. **查询逻辑**：<br>    1. 选「是」：…<br>        1. 错分移动人包含归位移动人。<br>        2. …<br>    2. 选「否」：…
```

禁止把子条件写成与父级同级的第二个 `1. 2. 3.` 序列（读起来像新开三条，不像子项）。

## PC 端按区域写（强制，默认遵守）

适用于 `pc-maintain-prd`、`pc-report-prd`，以及维护/报表页的版本增量。用户**没有**特别交代时，也必须按区域写；只有用户明确说「先写成一段 / 先列规则再说」时才可暂不拆。

| 区域 | 写什么 |
|---|---|
| **查询条件** | 筛选项的枚举、默认值、过滤逻辑、空值是否生效、联动 |
| **按钮操作** | 新增/编辑弹框字段、保存同步、导入/下载模版/导出规则与校验；弹框内容写在对应按钮说明列，不另开弹框小节；**维护页有导入时**按 [pc-maintain-prd](../pc-maintain-prd/SKILL.md)「导入写法」分层写（上传触发 → 导入校验 → 唯一性 → 整体成败），禁止一两句带过 |
| **数据列表** | 列展示文案、取值来源、空值展示、展示规则 |

同一字段若同时改查询、弹框、列表、导入：先可写一段**选项含义 / 历史迁移**等跨区域口径（短），再**分节**落到三个区域表里，禁止把「查询 + 新增编辑 + 列表 + 导入」揉进同一串 `1. 2. 3. 4.`。

**多 Tab 共用复杂规则：** 版本节内可先 `#### 公共规则`（见核心原则「公共规则 vs 禁止复述开篇」），再按 Tab 进三区；不要把重叠算法等在每个 Tab 按钮列复制四遍。

**反例（禁止）：**

```markdown
#### 是否混卸限制
1. 新增/编辑：必填；四档……
2. 保存后：同分拨同步……
3. 查询条件：枚举为……
4. 列表展示……
5. 历史数据……
6. 导入 / 下载模版……
```

**正例：**

```markdown
#### 是否混卸限制
（短表：四档含义 + 历史迁移一句）

##### 查询条件
|名称|说明| … |

##### 按钮操作
|名称|说明| … |   ← 含新增/编辑、导入、下载模版

##### 数据列表
|字段|说明| … |
```

```markdown
### V1.3.0
#### 公共规则（四个 Tab）
|项|说明|
|字段改名|…|
|与【对侧维护】重叠提醒|触发点 / 对比范围 / 分步判断 / 弹框（写全一次）|

#### 实时统一维护
##### 查询条件
…
##### 按钮操作
|新增|…本页校验通过后，按上述重叠提醒。|
##### 数据列表
…
```

纯计算/取数规则（无维护页界面）仍可按判定步骤或「匹配逻辑」表写，不强制套三区；一旦落在维护页或报表页**字段**上，仍按上表拆。

## Tab / 模块段首禁止复述三区（强制，默认遵守）

写维护页、报表页（含版本增量）时，**反复出现过**的问题：在「#### Tab 名」或「#### 某某字段」下面先写一大段「选库规则 / 跟库字段表 / 可自行维护字段表 / 删除联动」，后面查询条件、按钮操作、数据列表再写一遍同样内容。

**强制规则（用户未明确要求「先总述」时一律遵守）：**

1. **段首最多 1～2 句**：Tab 职责、本版主题、或跨区域短口径（如四档枚举含义表、历史迁移一句）。
2. **细则只出现一次**，落在对应区域：
   - 弹框字段、带出置灰、必填、校验、导入 → **按钮操作**
   - 筛选项 → **查询条件**
   - 列展示、一行规则、跟主数据实时展示 → **数据列表**
   - 跨 Tab 联动（如通用删库区连带删特殊行）→ 写在**触发侧或被影响侧的按钮说明**里，不要单独开「联动」长节再与按钮重复
3. **禁止**在三区前再用 `**某某规则：**` + 编号列表 / 字段表，把后文会写的内容提前抄一遍。
4. 写完自检：段首若删掉，后文三区是否仍能独立评审；若不能，说明细则还在段首——应下沉到三区。

**反例（禁止）：**

```markdown
#### 网点特殊配置
同页第二个 Tab。职责：……库区选自……跟库不可改……删除一并删……

**网点特殊选库规则：**
```

## 禁止写法

- 不写「本版没改什么」清单。
- 不写「其余同 V1.0.0」这类兜底废话。
- 不单独写「删除项」总表；删除内容放回对应模块。
- 不把基线版本全文复制一遍。
- 不重复别的文档已经讲清楚的配置项、字段枚举、页面限制。
- 不写“因为维护页已经禁止，所以计算侧也不匹配”这类自然成立的推导。
- 不写「查询条件 → 按钮 → 列表」等页面模块顺序（原型已确认时）。——**注意**：禁止写的是「复述页面上有哪几块」；**改动内容仍必须按这三块分区落笔**。
- 禁止把同一字段的查询/按钮/列表/导入规则写成一整段编号列表（见「PC 端按区域写」反例）。
- 禁止 Tab/字段主题段首再铺与三区重复的选库规则、跟库字段表、可维护字段表、联动长文（见上节反例）。
- 禁止在维护页写消费方运行时用法（命中后怎么拦/放行、面单怎么展示等）；只写维护侧字段与校验。

## 推荐结构

增量或修改类 PRD 优先按模块写：

1. **要解决的问题 / 用户调研 / 产品方案 / 需求价值**：每版必写（用户调研与产品方案同属业务分析，两项都要写；不知背景先问）。需求价值写业务帮助，不把产品方案再写一遍（见 [pm-incremental-prd](../pm-incremental-prd/SKILL.md)「需求价值」）。
2. **查询条件**：只写新增、删除、调整的查询项。
3. **按钮操作**：只写新增、编辑、导入、导出等本次变化；打开弹框的字段、取消/确定、提交校验写在对应按钮说明列，不另开「新增弹框」「编辑弹框」小节。**不要默认写查询、重置**（系统默认逻辑；有特殊逻辑才写）。
4. **数据列表**：只写新增、删除、调整的字段。
5. **验收要点**：只写本次涉及的内容；**必须用表格**列出（见下节），禁止只用编号列表。

不写「本版改动概述」。

## 验收要点（强制用表）

PC 端维护页 / 报表页 / 版本增量 PRD 写验收要点时，**默认用 Markdown 表格**，无用户明确要求时也要遵守。禁止写成纯 `1. 2. 3.` 编号清单。

推荐列：

|序号|验收要点|
|---|---|
|1|……|
|2|……|

可选加「模块 / Tab」列（多 Tab 或跨模块时）：

|序号|模块|验收要点|
|---|---|---|
|1|通用配置|……|

要求：
- 只列本版可验收项；回归项可写「与改版前一致」一条
- 每格一条，不在一格里塞无关多项（可用分号或短句，但一事为主）
- 维护页不写消费方运行时验收（放消费方 PRD）

## 跨文档取舍

- 维护页负责写：**怎么配**——字段、枚举、控件、导入模板、页面置灰/禁用、保存校验、列表展示规则、与对侧配置的**重叠提醒**（保存/导入前校验）。
- 消费方 / 计算逻辑负责写：**怎么用**——运行时匹配、取值、命中、放行/拦截、面单展示、兜底、**算薪闸门**（如命中后是否允许再进另一套规则）。
- 报表负责写：查询、统计口径、字段取值、汇总/下钻、导出；若本版**只改匹配/取数、页面查询列表未改**，按 [pm-incremental-prd](../pm-incremental-prd/SKILL.md) 写匹配逻辑表，不要为空造三区。
- **配置开关 vs 运行时闸门：** 开关字段（如「是否叠加特殊单价」）写在维护页；扫描/算薪时如何拦/放行写在计算或报表 PRD。维护页一句「闸门细则见【文档全称】，本页只负责配置与提醒」即可，**禁止**在维护页展开扫描步骤。
- **两套配置互斥 / 重叠（对称写）：** 两边维护页（或维护 + 消费方）**各写本侧视角**的触发点、对比范围、判断步骤、弹框；映射方向可相反但步骤同构。禁止只写一侧、另一侧空着或「见对侧全文」。
- **对齐对侧改版：** 可用「区间/匹配方式与【某某维护】特殊维护一致」；**禁止**把对侧整段区间矩阵、字段表再抄一遍。
- **维护页禁止写消费方具体用法**（如「命中本行时混卸放行」「面单仍显示某某」）；字段业务含义若需一句话，只写配置侧能理解的限制（必填、选项范围、不得与某某相同），用法细节放到对应业务 PRD。
- 如果某个限制已经在维护页禁止维护，计算逻辑里不要再写“禁止后自然匹配不到”。
- 如果前文已经列过**复杂**字段取值表，后文不要再贴整表；同版内可写「按上述「字段名」xxx 规则」，或直接写动作/删掉该步。简单查询条件各处写全。禁止「见 4.3」「见上文第四章」这类章节序号互引。

## 字段改名（多处同步时）

1. **公共规则**（或本版唯一入口）用短表/短列表写清：旧名 → 新名；注明「取值规则沿用现网，本版只改名称」。
2. 各 Tab **查询条件 / 按钮操作 / 数据列表**对应格子只写「原「××」改名」+ 枚举/默认/查询逻辑沿用现网（有增量才写增量）。
3. 禁止在每个 Tab 各抄一遍完整新旧对照长文。

## 表格写法

### 查询条件

长内容要拆开：

```markdown
|名称|说明|
|---|---|
|组合项|1. **删除**：「操作结算重量段」「体积段」。<br>2. **新增**：票-操作结算重量段、票-体积段、票-件数段。<br>3. **查询逻辑**：不变。|
```

### 按钮操作

按钮说明按动作分层，不把多件事塞一句：

```markdown
|名称|说明|针对变更记录|
|---|---|---|
|导入|1. **不支持导入**：按区间配置方案。<br>2. **支持导入**：不区分方案。<br>3. **拒收列**：区间维度、匹配维度、区间分列。|—|
```

### 数据列表

字段表只放字段；展示规则放最后一行。

**列数：**无二级字段时用 `字段 | 说明 | 补充说明` 三列；有嵌套分组时才用 `一级字段 | 二级字段 | 说明 | 补充说明` 四列，**不要**平铺字段也留空的二级字段列。

```markdown
|字段|说明|补充说明|
|---|---|---|
|分拨中心|算薪分拨|定时执行时写入|
|展示规则||1. 金额右对齐。<br>2. 无值展示 `-`。|
```

有嵌套时见 `pc-report-prd` 四列表写法。

## 语言风格

- 像产品经理写给研发/测试看的说明，不像宣传稿。
- 版本说明用日常说法：`这次主要是把配置方式改了` 可以，`配置内容升级` 少用。
- 复杂规则可以写清楚，但不要故意写长。
- 不确定的业务口径标「待确认」，不要替业务拍板。

### 业务规则书面表达（默认遵守）

撰写 PRD 中的业务规则说明时，请严格遵循中文产品文档的表达规范：

- 禁止使用 “靠、审、补” 这类口语化缩略简写，统一使用完整专业术语，如 “审核、补录、触发、支持、执行”；
- 禁止多重否定叠加的模糊表述，优先用正向肯定句式明确规则，否定表述必须完整清晰，避免 “不 XX 不 XX” 的歧义结构；
- 规则描述遵循「结论先行 + 路径补充」结构：先明确 “支持 / 不支持什么”，再说明正确的操作路径；
- 系统模块名用【】标注，功能操作用「」标注，保持格式统一；**页面/菜单必须写全称**，禁止「作业统计」「维护」「报表」「薪资」「交接单」等丢业务名的简称（例：写【移动作业统计】【移动自动合托提成方案维护】【移动自动合托特殊提成报表】【转运人员薪资】【交接单人员提成】；与 `pm-core`「页面 / 菜单 / 业务名词：必须写全称」一致）。
- **改名 / 新增 / 修订** 等动作必须带页面全称：写「【交接单人员提成】改名」「【转运人员薪资】新增「操作大票提成」」，禁止「交接单改名」「薪资新增」。

类似 “不靠审不通过自动补” 的表述禁止出现，必须改写为无歧义的完整句式。

**示例：**

| 不推荐 | 推荐 |
|---|---|
| 不靠审不通过自动补，靠重刷 | **不支持**通过「审核不通过」触发自动补录；须在【奖罚处理】对该类型执行「重刷」完成补录 |
| 有则不重复，无则补 | **支持**新建或执行「重算」；已存在对应凭证时纳入件数/金额后执行「重算」 |
| 跳过审核通过 | 「审核通过」运单**不纳入**「重刷」范围 |

### 通俗易懂（与 `pm-core` 一致）

与上一节同时遵守，互不替代：

- **通俗**指去掉研发/数据侧黑话，不是允许口语缩略。面向仓库运营、业务、研发、测试都能直接读懂。
- **名词写全称（强制）**：页面/菜单、字段、按钮、Tab、业务对象一律用系统正式全称；禁止自造简称（如「口数」「0 号口」「分拣方案」未带【】页名时易混）；禁止「交接单改名」「薪资新增」等丢掉【页面全称】的表头/小节。对接口语可首次括号注明（如隔口＝下货编号），正文仍用正式名。
- **描述不要偏技术**：能用「写进 / 取值相同 / 三份都写」说清的，不要用「同源写入」「落库固化」「固化」「字段映射」「关联键」「分桶」「落桶」「落数」「进数」等研发/数据侧黑话；一句业务话能说清就一句。
- 不用研发/数据侧黑话：存量、刷数、映射、兜底、运行时、递推、同源、固化、分桶、落数、进数（非页面正式字段名时）、切片（非业务字段名时）等 — 换成业务能看懂的说法。
- **节名 / 修订说明 / 跨文档引用锚点**一律用业务能读懂的短语；禁止「货量落数」「打标落数」「扫描落数」当标题。
- 数量、重量等比较关系可用 ≥、≤、<、>（如操作结算重量 ≤ 实际重量）；组合条件仍写清楚：**满足其中一个即可** / **两个都要满足**，不要写「OR 组合」「AND 组合」。
- 取数范围用例子：**算 7 月工资，连续看 2 个月，就看 5 月、6 月**，少写 M-N…M-1 这类公式。
- 功能未上线、没有历史数据时，直接写「本功能未上线」，不写「存量方案兜底」「待研发确认映射」。

**示例：**

| 不推荐 | 推荐 |
|---|---|
| 满足其一 OR 组合 | 满足其一：无破损或绩效分达标，有一个就行 |
| 无存量落库需刷数 | 本功能未上线，按新字段维护即可 |
| 三份货量上同源写入 | 卸车、码货、移动三份货量上都写，且取值相同 |
| 扫描落库固化后不回写 / 写入并固化 | 写入后不随方案/货区维护变更而改 |
| 按扫描时间分桶；落桶到各小时 | 按子单扫描时间归到各个小时段；按小时段归集统计 |
| 货量落数 / 扫描落数 / 子单落数 / 打标落数（节名或正文动词） | 节名如「写入货量明细的字段」「写入方案编号」；正文「扫描成功时写入货量明细」 |
| 落数、进数（非页面正式字段名时） | 写入 / 记入 / 生成货量 |
| 同样口数下；10 个口用 0～9；0 号口 | 同样「下货编号数量」下；下货编号数量=10 时用 0～9；0 号下货编号 |

### 跨表 / 跨报表取数

从另一张表、报表取标准或配置时，**写成一句业务话**：用什么条件匹配哪张表 → 本字段取对方哪个字段 → 未匹配到怎么办。

- 不要拆成「关联键」小标题 + 字段对照表 +「未关联到时」三截，除非字段很多、一句写不下。
- 匹配条件只列实际用到的维度即可；不必再写「不含某某字段」——没写进匹配条件的，本来就不参与匹配。
- 用「匹配」「取」「未匹配到」；少用「关联键」「字段映射」「关联失败兜底」。

**示例：**

| 不推荐 | 推荐 |
|---|---|
| 关联键：分拨 + 工号 + 岗位 + 月份（不含是否支援）。绩效工资对应报表「保底绩效」；未关联到时标准按 0。 | 根据分拨中心 + 人事工号 + 岗位 + 结算月份匹配【机叉叉车组长绩效标准报表】，取「保底绩效」；未匹配到时标准为 0。 |

### 字段计算写进说明列

算薪、提成等**字段取值逻辑**，写进该字段「说明」单元格（有序列表：匹配 → 取值 → 门槛 → 公式），不要在字段表下另起「从报表取标准」「实发计算」等小节。

- 规则**首次出现**时在该字段说明里写全；不写「见下文」「门槛见第 x 章」。
- 同一版内多个字段共用**同一套复杂规则**时：只在一处写全，他处用「按上述「字段名」xxx 规则」。
- **简单查询条件**（默认值、空不生效、短查询逻辑）：多 Tab 重复出现时**各处写全**，不要「按上述」。
- 表下只留展示、汇总、导出等**非单字段计算**的内容。

**示例结构（说明列内）：**

```markdown
1. **标准**：根据 … 匹配【××报表】，取「××」；未匹配到时标准为 0。
2. **绩效分**：根据 … 取【绩效分导入】对应岗位 tab；未取到则本字段为 0。
3. **发放门槛**：… → 本字段为 0。
4. 门槛满足：本字段 = 标准 × 绩效分 / 100 × 出勤系数。
```

# 用户说错时先确认，禁止盲从

## 用户原话（须遵守）

以后我如果有说的确实不对的地方你也要跟我说，跟我确认要不要改。

## 何时使用

- 用户纠正你写的方案 / 原型 / PRD / 对接记录
- 用户改口、合并/拆行、删字段、改规则时，你对照后发现**与事实或已确认口径冲突**
- 用户说「重复了」「写错了」「删掉」「改成某某」但现网或上文依据不支持

与 `pm-ask-before-guess`（缺信息先问）、`pm-discuss-challenge`（补视角标待确认）、`pm-core` 同时适用；本 skill 管**用户纠正未必对时怎么处理**。

## 必须做

1. **先判断对错**：对照现网页面/代码（uat）、已确认结论、本对话上文、已有 PRD。有依据才认定「用户这次说得不对」。
2. **先说清楚再动手**：简短说明「这里其实是……；你刚才说的点在于……；若按你说的改会变成……」。
3. **确认要不要改**：明确问「要按你说的改，还是保持现状？」**未确认前不要改文件**。
4. **用户拍板后再改**：说「还是拆开 / 就按我说的」→ 再改；说「那保持原样」→ 不改。

## 禁止做

- 明知用户说错了，仍立刻改文档/原型迎合
- 不解释依据，只回「好的已改」
- 把「用户随口一句」当成已推翻的正式结论去改历史口径（除非用户明确确认推翻）

## 与「给真实判断」的关系

| 情况 | 做法 |
|---|---|
| 用户说得对 | 按纠正改，可一句说明改了什么 |
| 用户可能看错 / 说错 | **指出 + 确认**，等答复 |
| 拿不准是不是错 | 说出依据与疑问，请用户拍板；不假装确定 |

## 产出前自检

- [ ] 本轮若按用户纠正改了文件，是否已确认该纠正本身成立？
- [ ] 若纠正可疑，是否已先问「要不要改」而不是直接改？

# PC 端原型（HTML 线框）

## 何时使用

- 用户要 **画原型 / PC 端页面 / 查询页 / 维护页 / 列表页 / 配置页界面**
- 处于 pm-core 工作流的 **原型阶段**（讨论已对齐方向，或用户明确要求出界面）
- 用户说「基于 PC 框架」「按通用后台布局画」

**不启用：**
- 用户只要讨论方案、不写界面
- 用户要写 PRD → 改用 `pc-maintain-prd` skill（须原型已确认）
- 用户要 Canvas、Figma、高保真视觉稿

## 母版（按项目选用，互不覆盖）

| 项目 | 母版路径 | 现网对照 skill（只读 uat） |
|------|----------|---------------------------|
| **DLC** / 数智分拨 | `docs/_共用/PC端通用框架.html` | [dlc-frontend-source](../dlc-frontend-source/SKILL.md) |
| **TVM** | `docs/_共用/PC端通用框架-TVM.html` | [tvm-frontend-source](../tvm-frontend-source/SKILL.md) |

- 画哪个系统的页面，就复制对应母版；**禁止**用 DLC 母版画 TVM 页，也禁止反过来
- 壳层色值 / 品牌文案以该项目 uat 现网为准；不确定归属时先问用户是 DLC 还是 TVM

**工作方式：**
1. **先确认项目**（DLC / TVM），选定上表母版
2. **先查是否已有该页面原型**：若 `docs/{项目名}/` 下已有对应页面的 HTML（同名或明显是同一维护页/报表页的历史原型），**直接在现有文件上改**，不要新增一个文件。用户明确要求另存新文件或拆版本文件时除外。
3. **没有现成文件时**：复制对应母版 → 放到对应项目目录，命名为 `docs/{项目名}/{中文页面名}.html`
4. **只改占位内容**（菜单名、标签页名、筛选字段、按钮文案、表格列名、行数）
5. **禁止从零发明新布局**；禁止改动顶栏 + 侧栏 + 四模块骨架结构

布局细节对照见 [reference.md](reference.md)（DLC 壳层）；TVM 色值与品牌见 [tvm-frontend-source](../tvm-frontend-source/SKILL.md)。
筛选/表单控件命名与 PRD 对齐时，对照 [pm-component-catalog](../pm-component-catalog/SKILL.md)（线框阶段仍用母版 HTML 控件形态，label 用标准组件名便于后续写 PRD）。

## 交付物

| 项 | 要求 |
|----|------|
| 格式 | 单文件 HTML（内联 CSS + 少量演示 JS） |
| 路径 | `docs/{项目名}/{中文页面名}.html`（与同项目 PRD 同目录） |
| 打开方式 | 浏览器直接打开，无需构建/后端 |
| 保真度 | 低 fidelity 线框；Ant Design 企业后台风格 |
| 依赖 | 不引 CDN、不接 API、不写后端逻辑 |
| **像真页面** | 原型就是实际业务页长什么样；**禁止**在页面上放「原型说明」、黄条注释、IT/PRD 备注、演示专用按钮文案 |

## 禁止页内说明（硬约束）

原型给业务/研发评审用，应看起来像即将上线的页面：

| 禁止 | 正确做法 |
|------|----------|
| 页面顶部/卡片内「原型说明：……」黄条、灰条、虚线备注框 | 说明写在对话回复或 PRD，不写在 HTML 页面上 |
| 「演示用」「仅示意」「一线不可见」「点某某按钮可看」等 meta 文案 | 用真实按钮、真实提示语、真实列表态表达 |
| 为讲解临时加的操作按钮（如「打开××（总额超限）」） | 走真实入口：点行、点编辑、点分配等现网路径；多状态用多行样例数据切换 |
| 把「只存表、列表不展示」的字段画成页面可见区并加注释 | 页面不画该字段；规则写 PRD |

异常提示（如超限红字）属于**真实页面会有的反馈**，可以画；但不要再加一层「这是演示」的说明。

## 按现网代码画字段（硬约束）

对照 DLC / TVM 源码画或改列表、查询、弹框时，**必须**启用 [pm-frontend-code-read](../pm-frontend-code-read/SKILL.md)：

- 先在对应项目 **uat** 读全表头/列/筛选项配置，再叠本期改名或新增
- **禁止**只读文件片段、只搜改动关键词、或用 PRD 增量列表冒充现网字段全集（曾导致【转运人员薪资】列对不上）

## 字段与文案：不清就问（硬约束）

画原型时，**截图识别不准、用户口述含糊、列表与弹框对不上**的，必须先问用户确认，**禁止自行拍板**后写进 HTML。

| 必须停下来问 | 举例 |
|---|---|
| 字段名看不清 / OCR 可能错 | 截图像「是否强制卸货」又像「是否混卸限制」 |
| 列表列名与新增/编辑弹框字段名不一致 | 列表「模型地址」、弹框仍是「辅助地址」 |
| 枚举项、占位文案、按钮文案拿不准 | 状态下拉是「有效/失效」还是「启用/停用」 |
| 查询条件有无、顺序、默认值未说明 | 所属分拨默认空还是带当前分拨 |
| 多图之间互相矛盾 | 两张截图同一字段文案不同 |

**做法：** 先列 1～若干条「待确认」问用户；确认后再改原型。可用占位「字段名待确认」临时占位，**不要**用猜的业务名充数。

能看清、用户已点名改过的，直接按确认结果改，不必重复问。

## 布局硬约束

### 全局结构（固定：左全高侧栏 + 右主区；色值按项目母版）

```
┌──────────┬────────────────────────────────────────────┐
│ 侧栏顶区  │ 顶栏（汉堡 + 页面标签 + 右侧工具/用户）       │
│ 品牌文案  ├────────────────────────────────────────────┤
│ 深色菜单  │ 主内容区（四模块，白底 Card）                 │
│ 可折叠    ├────────────────────────────────────────────┤
│          │ 页脚版权条                                  │
└──────────┴────────────────────────────────────────────┘
```

**结构共性（DLC / TVM 相同）：**

1. **左侧全高侧栏** — 宽 208px（折叠 54px）；顶区品牌 + 竖向菜单（白字，选中项用主题亮色）
2. **右侧主容器** — 主题色顶栏（汉堡 + 页签 + 右侧工具/用户）→ 主内容（浅灰底 + 白底 Card）→ 页脚
3. **禁止**再画「顶栏整行左品牌区 + 下方再接侧栏」的旧结构

**色值 / 品牌（按母版，勿混用）：**

| | DLC（ztpurple） | TVM（purple） |
|--|----------------|---------------|
| 侧栏底 | `#1c2531` | `#011040` |
| 顶栏 / 选中 | `#0658d9` | `#9174EA` |
| 主色（按钮等） | `#1890ff` | `#9174EA` |
| 内容底 | `#f2f3f7` | `#f0f2f5` |
| 品牌 | 数智分拨 \| DLC | Logo + TVM |

### 主内容区四模块（自上而下，顺序不可变）

| 序号 | 模块 | 硬约束 |
|------|------|--------|
| 1 | 筛选条件区 | 默认 **一行 3 个**筛选组件（下拉 / 输入 / 日期）；名称与控件 **左右布局**；最右侧固定 **重置 + 查询**，与筛选区 **最后一行底对齐** |
| 2 | 标签切换区 | 横向 Tab 条（纯框架，可切换 active 样式） |
| 3 | 操作按钮区 | 横向功能按钮组 |
| 4 | 数据列表区 | 标准表格：**首列复选框**；**分页固定贴在内容卡片底部且右对齐**（数据再少也贴底；表体多时在表格区内滚动）；表头与单元格文字默认 **居中对齐**；**表头字段名禁止换行**（`white-space: nowrap`），列多时靠表格横向滚动，不要把表头挤成多行 |

**分页 DOM（硬约束）：**

```
.table-area
  ├── .table-scroll          ← 只包表格，负责表体横/纵向滚动
  │     └── .data-table
  └── .pagination            ← 必须是 .table-area 的直接子元素；禁止放进 .table-scroll
```

- `.pagination` 使用 `margin-top: auto` + `justify-content: flex-end`，贴列表区**右下角**固定展示  
- **禁止**把分页写在 `.table-scroll` 内（否则会跟着表格滚动，或拉成整行宽条贴在表体后面）

### 筛选区扩展规则

- 每个 `.filter-item`：**左** `.filter-label`（右对齐固定宽）+ **右** `.filter-control-wrap`（控件）
- 用户明确要求多行筛选时：每行仍 **3 列均匀排列**，查询/重置 **只在最后一行右侧**（`.filter-area` 用 `align-items: flex-end`）
- 未说明行数时：保持 **单行 3 组件**

### 弹框 / 表单字段布局（硬约束）

- 字段名与输入控件必须 **左右排列**：**左** label（右对齐）+ **右** 控件；**禁止** label 在上、控件在下
- 与筛选区同一原则；多列表单可用 grid 排多列，但每个字段单元内部仍是左右布局
- 长 label（如「单人单月金额限制」）加宽 label 栏，不要改成上下叠放

### 样式约定（与所选母版一致）

卡片 `#ffffff`、边框 `#e8e8e8` 两套共用。顶栏 / 侧栏 / 主色 / 内容底 **以当前项目母版 CSS 变量为准**（见上表），不要把 DLC 蓝写进 TVM 页，也不要把 TVM 紫写进 DLC 页。

## 占位与命名规则

| 状态 | 写法 |
|------|------|
| 未确认字段 | 「筛选条件」「下拉框」「输入框」「列 N」「操作按钮 N」「标签 N」「菜单项 N」 |
| 讨论已对齐 | 填真实字段名 / 按钮名 / 列名 |
| 不确定 | 保留通用占位，不编造业务规则 |

## 最小交互（演示用，非业务）

保留母版中的演示交互即可：
- 侧边栏折叠/展开（顶栏汉堡，toggle `#layout.sidebar-collapsed`）
- 顶部标签 / 内容 Tab 切换 active
- 表头全选联动行 checkbox

不实现：查询、重置、分页跳转、菜单路由、表单校验。

## 与 pc-maintain-prd 衔接

```
讨论 → [pc-prototype] 出 HTML 原型 → 评审确认 → [pc-maintain-prd] 写 PRD
```

- 原型阶段：**不出 PRD 长文**
- PRD 阶段：**不擅自改已确认的原型交互**；若需改布局，回到原型阶段

## 常见变更速查

| 用户需求 | 改哪里 |
|----------|--------|
| 换筛选字段 | `.filter-grid` 内 `.filter-item`：`.filter-label` + `.filter-control-wrap` + 控件 |
| 多加筛选条件 | 在 `.filter-grid` 内追加 `.filter-item`，保持 3 列自动换行 |
| 换 Tab 名/数量 | `.content-tabs` |
| 加/减按钮 | `.action-bar` |
| 换表格列 | `<thead>` + `<tbody>` 列数对齐 |
| 换菜单/页面标签 | `.sidebar-menu` / `.page-tabs` |
| 不要内容 Tab | 与用户确认；极少数页面可去掉模块 2，须说明原因 |
| 不要复选框 | 与用户确认；维护页通常保留 |

## 产出前自检

- [ ] 已确认 DLC / TVM，并从**对应母版**复制（未混用另一套）；已有同页原型则**改原文件**，未另起新文件（用户明确要求另存除外）；文件名为中文，落在对应项目目录
- [ ] 若按现网代码画字段：已按 [pm-frontend-code-read](../pm-frontend-code-read/SKILL.md) 读全列配置后再改，未用片段/PRD 增量冒充全集
- [ ] 全局结构完整：左侧深色侧栏（品牌顶区 + 选中主题色）+ 右侧（主题色顶栏页签 + 主内容 + 页脚）；品牌文案与色值匹配当前项目
- [ ] 主内容四模块顺序正确：筛选 → Tab → 按钮 → 表格+分页
- [ ] 分页贴在内容卡片底部、**右对齐**（`justify-content: flex-end`）；分页是 `.table-area` 的直接子元素，**不在** `.table-scroll` 内；非紧跟表体后悬空、也不跟着表体滚动
- [ ] 筛选区：名称左+控件右；一行 3 组件 + 右侧重置/查询且与最后一行底对齐
- [ ] 弹框/表单字段：名称左+控件右（禁止上下叠放）
- [ ] 表格文字默认居中（含表头与数据单元格）
- [ ] **表头字段名单行不换行**（`th` 使用 `white-space: nowrap`；列多时横向滚动，禁止表头被挤成多行）
- [ ] 表格首列为 checkbox，底部有分页占位
- [ ] 单文件 HTML，无 CDN / 无后端
- [ ] **页面上看不到「原型说明」/演示备注/临时演示按钮**；呈现的是实际业务页
- [ ] 截图/描述不清的字段名、列表↔弹框不一致处已先问用户，未擅自定名
- [ ] 未确认信息用通用占位，不编造业务规则
- [ ] 未混用 PRD 输出

## 交付前必审

原型 HTML 写完后，**先启用** [pm-review](../pm-review/SKILL.md) 做布局/交互审查（有对应 PRD 时一并做字段对齐），输出「待你确认」清单后再结束本轮（用户明确说「先别审」除外）。默认只提问题，不擅自改文档。

**以后原型默认上传 Gitee，用 Gitee Pages 做在线预览；与 GitHub 无关；不再默认推公司 GitLab。**

|---|---|
| 仓库 | `hu_mian_fei/szfb`（本工作区 `origin`，SSH：`git@gitee.com:hu_mian_fei/szfb.git`，一般推 `main`） |

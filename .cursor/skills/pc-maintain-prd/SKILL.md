# PC 端维护页 PRD

## 何时使用

用户要写 PC 端维护/配置类页面 PRD，或已有原型/讨论结论需落文档时启用。
配合 pm-core 工作流：讨论、原型确认后再写 PRD；不擅自改已确认交互。

## 写法风格

必须同时遵守 [pm-prd-writing-style](../pm-prd-writing-style/SKILL.md)：只写有用内容；**字段/能力改动必须按查询条件、按钮操作、数据列表分区写（强制，无用户明确要求也要遵守）**；**Tab 段首只留一句职责，禁止再写与三区重复的选库/跟库/字段长节**；表格长内容拆有序列表，展示规则等非字段内容放表格最后说明行；语言用日常产品经理口吻。

控件/组件命名与说明列写法遵守 [pm-component-catalog](../pm-component-catalog/SKILL.md)：点名系统已有组件，只写本页业务差异，不重述大家熟悉的交互。

**禁止**：把某一字段的「查询 + 新增/编辑 + 列表 + 导入」揉成一整段 `1. 2. 3. 4.`。跨区域共性（如枚举含义、历史迁移）可在段首用短表说明，细则仍分别落入三区表格。详见写法 skill「PC 端按区域写」「Tab / 模块段首禁止复述三区」。

## 文档总结构

按顺序输出以下章节（无内容则写「无」或「待补充」）：

1. **概述** — 版本修订表，填写规则见下方「概述 · 版本修订表」
2. **要解决的问题** — 版本 + 问题描述
3. **业务分析**（两项都要写，不可省略）
   - 3.1 **用户调研** — 业务方诉求、使用场景、期望能力（按版本写；无调研内容写「无」并说明原因）
   - 3.2 **产品方案** — 按版本描述方案，表格列：**版本 | 产品方案**
4. **需求分析** — 需求价值、用户群体（岗位/部门/频次）、优先级及功能点
5. **详细需求描述**
   - 5.1 相关链接（ones、原型）
   - 5.2 权限说明（菜单权限、**功能权限/接口权限**、数据权限；无则写「无」或「沿用现网」）。功能权限须按本页实际按钮单独列出可配置项（如新增、编辑、删除、导入、导出），说明无权限时按钮不展示；不要只写数据权限漏掉接口权限
   - 5.3 需求描述（可先写全局注意事项：排序、提示语、菜单路径等）
   - **需求描述正文按版本分节（强制）**：在「需求描述」标题之下，用 `### V1.0.0` / `### V1.1.0` … 挂本版规则；**新建文档首版必须先写 `### V1.0.0`，再写模块细则**，禁止直接用 `### 5.2.1` / `### 5.3.1` 代替版本号
   - 若无独立「权限说明」节，需求描述可为 **5.2**，其下仍必须先 `### V1.0.0`
   - 版本节内再按 Tab/模块写（维护页见下方三区模板）；后续增量只新增 `### Vx.y.z`，不回改历史版本节

   - 若有变更记录 Tab，单独一节
   - **验收要点**（表格：`序号 | 验收要点`，强制；可放在对应版本节末）

## 概述 · 版本修订表

表格列：版本 / 修订人 / 修订时间 / 修订说明 / 开发负责人 / 测试负责人

| 字段 | 规则 |
|------|------|
| **版本** | 新功能默认 **V1.0.0**；后续改动按幅度递增：**V1.0.1**（小修小补、文案/字段微调）、**V1.1.0**（功能增强、新增模块/按钮/查询项）、**V2.0.0**（架构或业务逻辑大改、不兼容变更） |
| **修订人** | 固定 **胡绵飞** |
| **修订时间** | 取**当前日期**，格式 **YYYY.M.D**（到年月日即可，如 2026.6.29） |
| **修订说明** | **总结本版功能点**写入，一句话或分点概括本次交付范围 |
| 开发负责人 / 测试负责人 | 无信息则留空 |

后续版本在表中**追加新行**，保留历史版本记录，不覆盖旧行。

## 业务分析 · 用户调研与产品方案

章节标题固定为 **三、业务分析**。**3.1 用户调研**与 **3.2 产品方案**都必须写；缺一不可。

### 3.1 用户调研

写清业务方反馈与期望，可按版本分段或列表：

| 写法 | 要求 |
|------|------|
| 有调研 | 写谁提的、什么场景、期望系统怎么支持；与「要解决的问题」呼应，不写方案细节 |
| 无调研 | 写「无」或「待补充」，并一句话说明原因（如「本版为规则补齐，未单独调研」） |
| 后续版本 | 在本节**追加**本版调研要点，不覆盖历史 |

### 3.2 产品方案

小节标题固定为 **3.2 产品方案**，用表格按版本写方案摘要：

| 版本 | 产品方案 |
|------|---------|
| V1.0.0 | {方案描述：基于什么场景、通过什么能力、达成什么效果} |

- 与「要解决的问题」「用户调研」呼应，写**方案层**而非细节需求
- 版本号与概述表保持一致
- 后续改动追加新行

## 单个维护模块模板

每个 Tab 或功能块包含 **查询条件 → 按钮操作 → 数据列表** 三节，均用 Markdown 表格。

Tab 标题下**只写 1～2 句职责**（或不写），立刻进入三区；不要在三区前单独写「选库规则 / 跟库字段表 / 可自行维护 / 删除联动」等与按钮、列表重复的长节。

**多 Tab 共用复杂规则（可选但推荐）：** 本版若四个（或多个）Tab 共用同一套复杂逻辑（如字段改名清单、共用配置项默认值、与对侧维护页的重叠提醒整套步骤），在版本节内、各 Tab 之前先写：

```markdown
#### 公共规则（四个 Tab）
|项|说明|
|---|---|
|字段改名|…|
|是否叠加特殊单价|控件/枚举/默认/必填；不计入唯一性等跨区口径|
|与【对侧维护】重叠提醒|触发点 → 对比范围 → 分步判断 → 弹框（写全一次）|
```

随后各 Tab 仍按 **查询条件 → 按钮操作 → 数据列表**；按钮「确定 / 导入」写「本页校验通过后，按上述重叠提醒」。细则见 [pm-prd-writing-style](../pm-prd-writing-style/SKILL.md)「公共规则 vs 禁止复述开篇」「字段改名」。

**增量改某一字段时同样拆这三节**（只写有改动的区域即可），不要写成「#### 某某字段」下挂一串跨区域编号规则。

### 查询条件

| 名称 | 控件 | 说明 |

控件列用组件目录标准名（如数据权限组件、人员组件、多选下拉框）。说明列必须写清：
- 枚举项与**默认值**
- **空值是否参与过滤**（惯例：空 = 不生效）
- **查询逻辑**（包含 / 交集 / 精准匹配 / 时间区间交集）
- 联动与置灰规则（如有）

不要复述组件通用交互（可搜索、弹层多选等）。查询区布局约定：默认展示行数、展开规则（若适用）单独一句说明。

### 按钮操作

**无变更记录 Tab 时**（默认，如业务参数配置等标准维护页）：

| 名称 | 说明 |

**有变更记录 Tab 时**（如货量重量配置）：

| 名称 | 说明 | 针对变更记录 |

「说明」列按层次写：
1. **操作限制**（选中条数、状态、权限）
2. **弹框/页面** — 分区写：基础设定、匹配条件配置、业务参数等
3. 每个字段：**控件类型、枚举、默认值、必填、联动/置灰、输入限制**。**有枚举项必须写默认值**（含单选/多选下拉、单选按钮组；勿只写枚举漏默认）
4. **确定/提交校验** — 唯一性/重复校验、提示弹框
5. **提示文案** — 原样写出

**弹框写在按钮里，不单开小节：** 新增/编辑/复制等打开弹框的字段、取消/确定、提交校验，一律写在对应按钮的「说明」列；**禁止**在「按钮操作」外再单独写「新增弹框」「编辑弹框」「新增 / 编辑弹框」小节或字段表。

「针对变更记录」列：**仅在有变更记录 Tab 时写出**第三列；写保存成功后变更 Tab 的联动（修改类型、有效周期、历史记录截断规则）。**无变更记录 Tab 时不写该列、不单独说明。**

常见按钮按需选用：新增、编辑、批量编辑结束时间、**删除**、导出、下载模版、导入。

**默认不写「查询」「重置」：** 系统默认逻辑；除非用户明确说有特殊逻辑（如重置后某字段回到指定默认值且必须验收），否则按钮表不要出现查询/重置行。

**删除 vs 终止**：
- **默认写「删除」**：操作限制、确认提示（如「删除后不可恢复，请确认是否删除！（共 X 条）」）、删除后列表行为
- **特殊页面写「终止」**：仅用于重要规则/配置类、**不允许物理删除**的数据；需写清结束时间、状态、优先级重排等
- 用户未说明时，**优先用删除**；提到「不可删」「只能终止」「规则留痕」时再改用终止

### 导入写法（强制，有导入时）

按钮「导入」的「说明」列按 **上传触发 → 导入校验 → 唯一性校验 → 整体成败** 分层写，禁止只写「支持导入 / 整份失败」一两句。嵌套用缩进有序列表（表格单元格内用 `<br>` + 缩进空格）。

固定骨架：

```markdown
|导入|1. **上传触发**<br>    1. 点击导入按钮后获取用户本地文件，由用户手动选择，完成文件上传。模版：`{Tab名}_导入模版.xlsx`。<br>2. **导入校验**<br>    1. 校验导入文件内容是否符合**新增弹框**字段规则（本页额外限制写在括号内，如有效开始月、分拨仅可选适用分拨等）。<br>        1. 否：**整份文件导入失败**，自动下载失败文件，问题行提示具体失败原因。<br>        2. 是：进行**唯一性校验**。逻辑：<br>            1. **{维度一，如有}**<br>                1. 根据**{唯一键字段组合}**校验已维护数据（写清状态范围，如生效中、待生效）是否重复。<br>                    1. 数据不重复：校验通过。<br>                    2. 数据重复：根据**有效期限**与上一步重复数据的有效期限校验是否有交集。<br>                        1. 无交集：校验通过。<br>                        2. 有交集：校验不通过。<br>            2. **{维度二，如有}**（键不同时另起一支，勿与维度一混写）<br>                1. …同上结构…<br>            3. **整体导入成功/失败规则**<br>                1. 校验范围：文件全部数据行（含各维度）。<br>                2. 导入判定逻辑：<br>                    1. 全部数据校验无误 → 整份文件导入成功。<br>                    2. 任一数据校验不通过 → **整份文件导入失败**，自动下载失败文件，问题行提示具体失败原因。|
```

|要求|说明|
|---|---|
|字段规则对齐新增|写「符合**新增弹框**字段规则」；本页相对新增的额外限制（补录窗口、下拉范围等）写在同一句括号或子条里|
|唯一键按维度拆开|分拨 / 人员 / 全国等维度**分条写**，每支写清「用哪些字段判重复 → 再判有效期限是否有交集」；无多维度则只写一支|
|撞期默认禁止覆盖|与已维护有效月有交集 → 校验不通过；除非用户明确要求「覆盖 / 截断旧方案」|
|整份成败|任一行字段或唯一性失败 → 整份失败并回传带行级原因的失败文件；全部通过才成功|
|模版名|上传触发里写清 `xxx_导入模版.xlsx`|
|不做导入|明确写「不做导入」或不出现导入按钮，勿留空壳|

### 新增确定校验写法（强制，有新增弹框时）

「确定」按钮的校验与导入同一套分层：**字段规则 → 唯一性（按维度）→ 通过保存 / 不通过提示**，禁止只写「必填完整；撞期禁止保存」一两句。

```markdown
2. 确定：
    1. 校验是否符合**新增弹框**字段规则（本页额外限制写括号内）。
        1. 否：不保存，按字段提示完善必填/输入限制。
        2. 是：进行**唯一性校验**。逻辑：
            1. **{维度一，如有}**
                1. 根据**{唯一键}**校验已维护数据（写清状态范围）是否重复。
                    1. 数据不重复：校验通过 → 关闭弹框，保存成功。
                    2. 数据重复：根据**有效期限**与上一步重复数据的有效期限校验是否有交集。
                        1. 无交集：校验通过 → 关闭弹框，保存成功。
                        2. 有交集：校验不通过 → 提示数据重复，不保存。
            2. **{维度二，如有}** …同上结构…
```

有二次确认（如单价非正数）写在字段规则通过之后、唯一性之前。导入的唯一性口径须与新增「确定」一致。

**简单维护页**（无变更记录、无时效、唯一键仅编码等）：仍用上述两段骨架，唯一性可压成「按编码是否与已维护重复」一支，不必硬写分拨/有效期限。

**有变更记录 Tab**：导入说明列写法同上；第三列写变更联动（修改类型、有效周期等）。新增确定通过后的变更联动仍写第三列。

### 数据列表

| 字段 | 说明 | 双击事件 |

说明列写：取值来源、空值展示（如「-」）、格式、状态判定、展示样式。
双击事件：跳转、弹窗、切换 Tab 等；无则留空。

## 变更记录 Tab（可选）

**仅当页面有审计/追溯需求时**才单独写一节，此时按钮操作表使用三列（含「针对变更记录」）。

结构：
- 查询条件（变更类型、方案编号、有效周期、变更人/时间等）
- 按钮（通常仅导出；按钮表为两列 `名称 | 说明`）
- 数据列表 + **变更对比弹窗**（变更前/后列，变更字段标色）

主列表双击勾选行 → 跳转变更记录 Tab 并自动查询，为常见联动，按需描述。

## 验收要点

每个维护页 PRD（含版本增量）须有 **验收要点** 节，**强制用表格**：

|序号|验收要点|
|---|---|
|1|……|

只列本版可测项；写法细则见 [pm-prd-writing-style](../pm-prd-writing-style/SKILL.md)。

## 模块继承 / 差异写法

多 Tab 逻辑高度相同时，**不要全文复制**。写法：

> 功能整体与「{基准 Tab 名}」保持一致，仅存在以下差异：
> 1. …
> 2. …

差异点限定在：枚举值、字段名联动、导入模版名、校验范围等。

## 写作原则

- 写**用户可见的维护行为**（怎么录、怎么校验、怎么展示），不写表结构、接口协议；**不写消费方运行时怎么用这批配置**（交给对应业务 PRD）
- 字段/状态名与原型、现有系统保持一致；不确定标「待确认」
- 每个操作写清：**正常路径 + 校验失败 + 边界**（如整份导入失败）
- 各种操作的**提示语**单独写出，不省略
- 注意描述**数据排序规则**
- 分拨纬度 / 全国纬度 校验逻辑分开写，不要混写

## 产出前自检

- [ ] 概述版本表：版本号规则正确、修订人为胡绵飞、修订时间为当天日期、修订说明已概括功能点
- [ ] 业务分析已含 3.1 用户调研与 3.2 产品方案表（版本 | 产品方案），两项均有内容（无调研须写明「无」及原因）
- [ ] 产品方案与「要解决的问题」、用户调研呼应
- [ ] **字段改动已按查询条件 / 按钮操作 / 数据列表分区，无跨区域一整段编号清单**
- [ ] **多 Tab 共用复杂规则已用公共规则写一次**（若有）；三区未把重叠算法等复制多遍；未用「本页做两件事」复述三区
- [ ] **Tab 段首无与三区重复的选库/跟库/可维护字段长文**（细则已落在按钮或列表）
- [ ] **运行时闸门已外置**（维护页仅配置 +「细则见【文档全称】」）；与对侧重叠时本侧视角已写全
- [ ] 每个查询条件都有默认值 + 空值是否生效 + 查询逻辑
- [ ] 新增/编辑弹框：**有枚举项的字段均已写默认值**（不只查询条件）
- [ ] 每个按钮都有操作限制 + 弹框字段 + 提交校验 + 提示语；**新增「确定」已按字段规则 → 唯一性 → 保存/提示分层写**；**未默认写查询/重置**（无特殊逻辑时）

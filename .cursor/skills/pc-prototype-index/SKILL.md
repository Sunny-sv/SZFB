# PC 原型索引同步

## 背景

Gitee Pages 预览入口是仓库根目录的 `index.html`，按项目分组列出 `docs/{项目名}/*.html` 的链接。这一步是手动维护的，容易在「新增原型」提交里漏掉，或者要滞后一次单独提交才补。原型默认发布到 Gitee（见 [pc-prototype](../pc-prototype/SKILL.md)「上传仓库」）。

## 何时使用

- 用户刚创建/移动/重命名了 `docs/{项目名}/*.html` 原型文件
- 用户说「更新索引」「同步预览」「加个链接」「检查一下 Pages 能不能打开」
- `pc-prototype` 画完原型收尾时，主动确认一遍索引是否需要同步——不要默认已经同步

## 操作步骤

1. **扫描现状**：列出 `docs/**/*.html`（`docs/_共用/PC端通用框架.html` 母版归入「共用」分组，其余按一级目录归入对应项目），与 `index.html` 里已有的 `<a href="...">` 逐条比对，找出：
   - 磁盘有、索引里没有的文件（漏加）
   - 索引里链接的文件已经不存在的（可能被重命名/删除，需要用户确认要不要删掉这条，不要自作主张删）
2. **补齐分组**：`index.html` 按 `<div class="group"><h2>{项目名}</h2><ul>…</ul></div>` 分组，项目名对应 `docs/` 下的一级目录名：
   - 已有对应分组：在该分组 `<ul>` 内追加一条 `<li>`
   - 没有对应分组：在最后一个分组之后、`<p class="note">` 之前新增一个 `<div class="group">`
3. **生成显示名**：默认用文件名去掉 `.html` 后缀作为链接文字；文件名里用短横线表达「主标题-子说明」的（如 `外包公司维护2.0-优化.html`），可参照现有条目风格转成「主标题（子说明）」（如「外包公司维护 2.0（优化）」）。拿不准就保留原文件名，问用户要不要改。
4. **保持格式一致**：不改动 `<style>`、不调整已有分组的顺序，新条目的缩进、引号风格跟同分组里的其它 `<li>` 保持一致。
5. **提示后续**：改完提醒用户——如果仓库之前已经开过 Gitee Pages，推送后到「服务 → Gitee Pages」点一次「更新」；如果链接始终打不开，检查部署分支是否为 `main`、目录是否为 `/`（根目录），且仓库为公开。用户点名「上传原型」时按 [pc-prototype](../pc-prototype/SKILL.md) 推到 Gitee。

## 不做的事

- 不改 `docs/{项目名}/*.html` 原型本身的内容
- 不判断原型内容画得对不对（那是 `pm-review` 的事）
- 不动 `首页门户.html`（这是独立的业务门户页面原型，不是预览索引；除非用户明确说要把它也当成索引入口维护）

## 产出前自检

- [ ] 新增的原型文件都能在 `index.html` 里点到
- [ ] 没有破坏原有分组结构和样式
- [ ] 新条目的显示名跟同分组里其它条目风格一致
- [ ] 索引里没有指向已删除/改名文件的死链接（或已经跟用户确认要保留）
